# Axiia Cup — UX Journey Audit

基于 UX Journey Designer 框架的完整用户旅程审计。对产品每个页面进行认知负荷量化、5 Gate 测试、反模式检测。

## 二、iPhone Test: 5 Gate 检测

### Gate 1: 单一主要行动

| 页面 | 主要行动 | 结果 |
|------|---------|------|
| Landing | 注册 | **PASS** — 一个 CTA，清晰 |
| Register | 输入邮箱 | **PASS** |
| Login | 登录 | **MARGINAL** — "进入工坊"是正确的行动但标签错误 |
| Workshop | 写提示词 | **FAIL** — 三个竞争任务：阅读规则、写提示词、选择模型。用户目光没有焦点。 |
| Dashboard (空) | 去工坊 | **FAIL** — 不存在任何行动。"暂无最近对局。"是死胡同。 |
| Leaderboard | 浏览结果 | **PASS** — 但二级行动（点击进入对局详情）的引导很弱 |

### Gate 2: 我在哪里？我能去哪里？

导航栏一致：控制台 / 工坊 / 排行榜。高亮状态可见。**整体 PASS。**

但在工坊内部：无进度指示器（"第 1 步共 2 步：写商鞅的提示词"）。没有"你的版本已保存"或"你还没有保存版本"的指示。**工坊内部 FAIL。**

### Gate 3: 展示结果，而非机制

**全产品严重失败。**

- 工坊展示原始计分公式（+1, -0.25, -0.75）而不是展示赢了是什么样子
- 工坊展示完整的裁判 prompt（机制）而不是"裁判偏好谨慎、有据可查的论点"（结果）
- 工坊展示"真诉求数: 1, 从诉求中随机选 1 条作为真诉求"（机制）而不是"每局你会有 1 个真实目标和 2 个诱饵 — 骗裁判同意你的真目标"（结果）
- Landing 展示"瑞士轮赛制按胜场和小分排序"（机制）而不是展示一个实际的排行榜截图或对局精彩片段（结果）

唯一展示结果的页面是 Match Detail。其他所有页面都在解释机制。

### Gate 4: 每个状态都经过设计

| 状态 | Dashboard | Workshop | Leaderboard |
|------|-----------|----------|-------------|
| 空状态 | "暂无最近对局。" **死胡同** | N/A（总是有规则） | N/A |
| 加载中 | 未指定 | 未指定 | 未指定 |
| 错误 | 未指定 | 未指定 | 未指定 |
| 成功 | 未指定 | "保存版本" → 无可见确认 | 未指定 |
| 首次使用 | 与空状态相同 **无引导** | 与老用户相同 **无引导** | 与重度用户相同 |

**除了有数据的主路径之外，所有状态都未设计。**

### Gate 5: 渐进式披露

**工坊严重失败。**

所有内容同时披露：
- 5 个规则 section 全部展开（角色详情、机制参数、比赛流程、计分规则、裁判视角）
- 完整系统预设提示词可见
- 两个角色 tab 可见
- 模型选择器可见
- 字数统计可见

首次用户需要的是："你正在为商鞅写策略。这是他想要什么。写你的提示词。" 就这些。其他所有内容都应该是渐进式披露。

## 四、反模式检测

| # | 反模式 | 位置 | 严重度 |

## 五、严重问题排序（按用户影响）

### 1. 工坊认知过载（26/8 预算）

- **会发生什么**：首次用户打开工坊，看到关于计分、诉求、裁判逻辑的文字墙和两个角色 tab。冻住。
- **为什么痛**：这是核心动作（写提示词）发生的唯一页面。如果用户在这里跳出，产品价值为零。
- **修复**：分阶段工坊。首次访问只显示：一句话游戏摘要 → 示例对局链接 → 商鞅的提示词文本框（带模板/起始内容）。其他内容在"显示完整规则"开关后面。
- **工作量**：M

### 2. 首次保存前没有任何具体示例

- **会发生什么**：用户阅读关于计分公式和诉求机制的抽象规则。从未看到实际对局长什么样。
- **为什么痛**：Gate 3 违规。展示机制而非结果。用户无法形成关于自己正在构建什么的心智模型。
- **修复**：在工坊页的提示词编辑器上方嵌入 3 轮对局摘录（来自 match #347 的真实数据）。"这是一场真实对局的片段。你的提示词决定了你的 AI 会怎样辩论。"
- **工作量**：S

### 3. Dashboard 空状态是死胡同

- **会发生什么**：新用户导航到控制台，看到四个破折号和"暂无最近对局。"
- **为什么痛**：零引导，零动力，零下一步。用户没有理由回来。
- **修复**：空状态带三个可操作卡片："编写你的第一版策略 →" / "看看别人怎么赢的 →" / "了解比赛规则 →"
- **工作量**：S

### 4. Match Detail 页面对新用户不可达

- **会发生什么**：产品中最好的教学工具（完整对局记录 + 计分分解）需要：登录 → 排行榜 → 点击一场对局。没有对局的新用户没有理由去排行榜。
- **为什么痛**：产品最好的内容被锁在最差的 UX 路径后面。
- **修复**：在三个位置添加"查看示例对局"链接：工坊页、Dashboard 空状态、Landing 页。一场精选对局，硬编码。
- **工作量**：S

## 六、整体设计评估

### 有效的部分

- **暗色主题是正确选择。** 竞技竞赛 + 古代宫廷阴谋。暗色传达严肃、竞争和氛围。暖橙色强调色（#e85d3a）在暗色表面上醒目。
- **Match Detail 页是产品中设计最好的页面。** 带回合编号的完整对话记录、隐藏信息揭示、裁判判词、逐步计分分解。一页就能教会你整个游戏。
- **等宽 AXIIA CUP logo** 有效。干净、有记忆点、竞技感。
- **导航栏** 一致，高亮状态清晰。

### 无效的部分

- **产品没有超越"暗色"的视觉身份。** 移除文字内容，你无法辨别这是关于古代中国宫廷辩论的游戏。它看起来像任何 SaaS 仪表板。
- **工坊是一个页面承担三个工作**：规则手册 + 提示词编辑器 + 教育资源。三者相互打架。
- **排行榜数据丰富但故事贫乏。** 18 个玩家，数字列。没有叙事。谁在上升？最戏剧性的对局是哪场？
- **没有观众模式。** 对局记录非常有趣（两个 AI 用古典中文争论秦国变法），但你必须注册登录才能看到。产品坐在内容金矿上却把它锁起来。

## 七、Quick Wins（每个 < 1 小时）

1. **折叠工坊 accordion** — 改变默认状态为折叠（角色详情除外）。每个 accordion 改一个 prop。
2. **在 tab 上方加"你需要同时编写两个角色的策略"** — 一行 JSX。消除最大"等等，为什么有两个？"困惑。
3. **Dashboard 空状态** — 将"暂无最近对局。"替换为引导性空状态 + CTA 到工坊。
4. **登录按钮标签** — 将"进入工坊"改为"登录"。首次用户不懂工坊。
5. **保存按钮下方加"你可以随时修改，比赛前自动使用最新版本"** — 减少保存焦虑。
6. **排行榜"小分" tooltip** — 给列头添加 `title="所有对局得分总和，用于同胜场排名"`。
7. **工坊 textarea 占位符** — 从"为 商鞅 编写策略提示词..."改为"例如：在辩论中强调变法对秦国军事力量的具体提升，用河西之战的失败作为论据..." — 展示提示词长什么样。

## 八、建议的新用户引导流程

现在不存在。应该有。

| 步骤 | 用户看到 | 用户学到 | 用户做 | 下一步 |
|------|---------|---------|-------|--------|
| 1. Landing | 3 轮对局摘录 + "用提示词打造最强对话智能体" | "AI 用角色身份辩论，我控制它们说什么" | 点击注册 | → Register |
| 2. Register | 邮箱 → 密码 → 昵称 → 邀请码 | "我在加入一场比赛" | 完成表单 | → Workshop（引导模式） |
| 3. Workshop（首次） | 引导卡片："你的第一个任务：为商鞅写一份策略" + 30 秒说明 + 示例提示词模板 | "我写提示词，AI 用它来辩论" | 粘贴/编辑模板，点击保存 | → 成功状态 |
| 4. 保存成功 | "已保存！你的商鞅准备好了。接下来写甘龙的策略。" + 甘龙 tab 自动聚焦 | "我需要写两边" | 写甘龙提示词，保存 | → Dashboard |
| 5. Dashboard（首次） | "策略已就绪！等待下一轮比赛开始。先去看看别人的对局？" + CTA 到排行榜 | "等待期间我可以学习别人的策略" | 浏览排行榜 → 点击对局 | → Match Detail |
| 6. Match Detail | 完整对话记录 + 计分分解 | "现在我理解了计分、诉求、裁判" | 阅读，回到工坊迭代 | → Workshop（回访模式） |

**核心洞察：Match Detail 页就是教程。** 不要试图用规则解释游戏。给他们看一场游戏。然后他们重新阅读规则时就会理解。
