# 天梯：胜率匹配与演示（2026-10-20）

## 页面

`/sortie` 是正式天梯入口。手机底栏采用已确认的方案 08：44px
上凸圆形按钮，未选中灰底浅灰双剑，选中红底白双剑；桌面顶部与其他 tab
同等处理。页面和 tab 均命名为「天梯」。

场景舞台、统计、缩略图和出战区沿用已确认的本地
demo。场景画使用现有介绍页素材：商鞅橙黄、码头蓝、本能寺紫、凤仪亭粉、电车绿；电车使用自动驾驶一案的第二张图。整个场景卡链接到介绍页。

显示当前参赛智能体累计天梯胜率、当前连胜、个人最高连胜，以及当前场景所有有效参赛智能体的最高胜率。没有完局时显示「—」。不显示赛季、定位期或匹配规则入口。

本能寺每个阵营卡上方的「更换角色」只选择角色，不选择智能体或版本，不改参赛标记。自动使用该角色已有参赛版本；没有时使用所有场景共有的「设置参赛版本」引导。卡片只选择出战阵营。尚未解锁时，「去练习」进入当前参赛版本的智能体主页，自动打开
NPC 练习页签。

## 正式接口和统计

- `GET /v1/ladder?scenarioID=…`：当前玩家参赛智能体及累计记录、当前场景最高胜率；不返回其他玩家提示词。
- `POST /v1/ladder/pairings { versionID }`：后端从同场景、对侧、其他玩家的有效参赛版本中选择对手，返回
  10 分钟有效的配对 ID 和公开身份。此步不创建对局、不扣积分。
- `POST /v1/ladder/pairings/:id/start`：用户在对手揭晓后点击「开始对局」，后端验证归属、参赛状态、门槛、配额、积分和模型政策，创建一场异步
  PvP，返回现有战报地址的
  matchID。相同配对重复启动返回同一局；版本变化或过期需重新匹配。

统计属于
agentID，跨该智能体的所有参赛版本累计，不因换版本清零。仅完成、评分成功的天梯对局计数；普通
PvP、NPC、锦标赛、运行失败不计入。平局计入总场数并中断连胜。胜率为 wins /
(wins + losses + draws)。

匹配分数为 `(wins + 0.5 * draws + 5) / (games + 10)`。优先取分差 5、10、20
个百分点内的最窄非空集合，否则使用全部合资格对手。没有新手独立池或胜率硬门槛。按玩家均匀抽选，再选其参赛智能体；对手无需在线或点击匹配。

配对和 matchID
的关联在同一数据库事务中写入，重复创建不能产生第二局。沿用现有异步
actor、重启恢复、积分预留和失败补偿。战绩从已完成对局派生，重复结算事件不会增加计数。

## 前后端发布边界

Swift 实现在 `paideia-ai/axiia-cup-v2` 的 `codex/agent-ladder`
分支。先发布后端及新增 `ladder_pairings`
表，再发布前端。新增表属于向前迁移；旧后端镜像可能拒绝包含新表的数据库，回退需保留兼容
schema 或恢复已验证备份。此任务不操作生产服务。

普通构建读取真实接口。`VITE_SORTIE_DEMO=true`
选择演示页，`VITE_SORTIE_BROWSER_DEMO=true` 额外开启浏览器内隔离的模拟
API；两者只用于演示构建。演示使用虚构数据，不访问线上
API、不调用模型或扣真实积分，刷新重置。

本地：`deno task preview:sortie`。Vercel：`deno task build:sortie-demo` 后只上传
`build/vercel-demo`。入口为 `/demo/mobile.html` 和 `/sortie`，底栏方案比较在
`/demo/nav-options-v2.html`。

验证覆盖正式构建的浏览器交互、服务端选择对手、显式开局、角色缺参赛版本、过期恢复、NPC
跳转、积分与重复请求、跨版本统计和数据库迁移。浏览器合同测试使用 HTTP
样本；Swift HTTP 测试运行真实数据库与异步执行器，模型为离线测试模型。
