# 成就系统实施计划

本次交付包含 Axiia Cup 的 31 项账号成就、通知与弹窗、历史补算，以及使用实际前后端代码的本地预览。前端起点为 `d60bf3e`，Swift 服务起点为 `864543e`；两个仓库均使用 `codex/achievement-integration` 分支。

## 已确认的产品规则

- 删除无字天书；其余四项原候选全部启用，合计 31 项。
- 赏金指发起方获胜后领取的积分返还；首笔与单日 30 笔均从实际领取记录判断。单日规则使用 Asia/Shanghai；30 笔要求对局和领取都在同一天。
- 历史只补算证据完整且资格可确认的记录，记录原始获得时间，静默保存，不批量弹窗或播放音效。
- 所有未解锁成就显示统一方形问号；不透露名称、描述、进度或真实图标。已解锁按金、银、铜展示完整描述。
- 账户新增成就中心卡片，行为同归档智能体入口。全局弹窗采用确认的 02「全幅封面」：左侧完整方形成就图，右侧标题与带中文引号的趣味文案；不显示达成条件，空文案不显示空引号。点击用新标签页打开成就中心。
- 成就音效选用 11「原版三音」，继续使用最初的 0.58 秒产品合成音及现有静音、音量和去重策略。
- 通知清空、已读、弹窗已展示、成就已获得是独立状态。

## 实施顺序

1. 固定清单、角色别名、接口及证据模型，明确玩法规则与历史证据边界。
2. 并行实现 Swift 成就规则、持久化与 API，以及前端中心、通知、弹窗和音效。
3. 把对局结算和积分返还接入规则执行，增加可靠有效运行区间记录，提供幂等历史补算。
4. 启动独立本地数据库和实际 Swift 服务，服务同一份前端生产构建；账号经真实 API 创建，隔离导入的参考战报由服务端规则计算成就。
5. 完成规则、服务端契约、前端单元和浏览器验证，审查差异，提交并推送两个仓库。

## 接口约定

`GET /v1/achievements` 返回 `{ achievements, eventCursor }`。快照与游标来自一致的数据库视图。锁定项仅含匿名 `id`、`tier` 和 `unlocked: false`；已解锁项增加 `title`、`flavor`、`description`、`iconURL`、`unlockedAt` 和可空 `matchID`。档位为 `gold`、`silver`、`bronze`，时间为 Unix 秒。

`GET /v1/achievements/events?after=N` 返回 `{ events, cursor }`。每个事件包含单调 `id`、已解锁成就、可空 `notificationID`、`occurredAt` 和 `source`（`live` 或 `backfill`）。全局监听器按游标读取，账号切换时重置，断线可恢复；历史事件不播放庆祝提示。

## 验收要求

- 所有 31 条规则均有正反边界覆盖；角色集合固定五场景 12 席位；失败、热座、自我对战和测试用途不误计。
- 重复结算、重复领取、重放和重复补算不能重复授予或重复通知；被动迎战正常累计。
- 连胜按完成时间排序；新对局同秒时按事务内持久化的结算顺序，历史同秒记录以 match ID 稳定排序。日累计遵守上海日界；短提示词不能用未计数字符绕过。
- 有效运行时间排除队列、暂停、失败调用与重试退避，重叠区间只计一次；历史无证据不猜测。
- 锁定内容不出现在账号响应、DOM 或无障碍标签中；真实图标仅用于已获得项。
- 弹窗新开标签页；多成就排队；重连、刷新、多标签页不重复庆祝；静音和音频未启用不影响可见提示。
- 通知全部已读或清空后，新解锁通知仍出现并保持未读。
- 浏览器验证覆盖账户入口、三档成就、完整描述、问号占位、通知、弹窗、移动端和键盘操作。

## 本地预览边界

预览使用这次分支的实际产品 UI、Swift API 与独立数据库。测试账号和测试对局与线上数据隔离；不向生产数据库注入演示数据。代码与合并后的行为一致，真实线上账号数据和外部模型服务可用性取决于部署环境。

## 本地联调复现

1. 在配套 Swift 分支生成构建清单，通过 Bazel 构建 `//packages/axiia:axiia`。
2. 为 `axiia serve` 设置独立 `AXIIA_DB_PATH`（目录名包含 `achievement-preview`）、锁文件和对象目录，监听 `127.0.0.1:8094`，设置本地 elevation secret、`AXIIA_COOKIE_SECURE=false`，允许来源 `http://127.0.0.1:5184` 与 `http://localhost:5184`。不使用生产数据库。
3. 服务启动后，使用 `axiia admin mint` 创建本地管理员，再用管理员凭据依次运行 `v2/web/e2e/seed-achievement-scenarios.ts` 和现有 `seed-dev.ts`。前者装入本仓库当前五个场景脚本，后者通过真实 API 创建账号和智能体。
4. 正常停止本地服务，运行 `python3 v2/web/e2e/seed-achievement-history.py <独立数据库路径>`，导入参考战报与明确标记的本地测试对局。脚本拒绝非空对局数据库，不直接写入成就。
5. 对该数据库运行 `axiia achievements backfill` 检查预期授予，再运行 `axiia achievements backfill --apply`。重复执行应为零新增。重新启动服务。
6. 在 `v2/web` 运行 `deno task build` 和 `deno task preview:achievement-toast:build`，再运行 `deno task preview:achievements`。预览直接提供生产构建，将所有 `/v1` 请求转发到实际 Swift 服务。`/_preview/achievement-toast/` 导入同一正式弹窗组件和音效，可反复试听选定方案，不写入账号成就或对局数据；`/_preview/achievement-toasts` 保留所有设计候选。
7. 运行 `AXIIA_ACHIEVEMENT_PREVIEW=1 AXIIA_BASE_URL=http://127.0.0.1:5184 deno run -A npm:playwright test tests/e2e/achievements.real.spec.ts`。测试使用 `tieyan@axiia.test`；留给人工体验的 `jiangpan@axiia.test` 仍保留待领取胜局，两者密码均为 `seedpw-123456`。

两个仓库需要配套发布：先提供服务端新接口、结算与补算，再发布成就前端。历史补算在规则版本首次启动时静默执行；日常结算和积分领取使用相同持久化规则，重复执行不重复授予。
