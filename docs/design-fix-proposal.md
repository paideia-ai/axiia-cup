# Axiia Cup UX Fix Proposal

基于浏览器实测的首次用户旅程分析。核心问题：从注册到写出第一版提示词的认知负荷太高，中间缺少反馈回路。

---

## 问题总览

```
Landing (模糊) → 注册 → 登录 → 工坊 (信息轰炸) → 保存 (然后呢？) → ???
```

用户必须：读 2000 字规则 → 理解 4 变量计分公式 → 理解真假诉求机制 → 发现要写两个角色 → 写两份 1000 字提示词 → 保存后等管理员开赛。全程零反馈、零示例。

---

## Fix 1: Landing Page — 用一场真实对局代替三步说明

**现状：** "01 编写提示词 → 02 自动对战 → 03 排行竞技" 三步抽象说明，用户看完仍不知道实际体验是什么。

**方案：** 把三步说明替换为一段精选对局的高亮回放（3-4 轮精彩对话 + 裁判判词摘要 + 最终比分）。不需要完整 transcript，只要让用户在 30 秒内看到：

1. 两个 AI 角色在朝堂上唇枪舌剑
2. 裁判（秦孝公）做出裁决
3. 一个比分结果

**实现复杂度：** 低。从现有对局数据中选一场精彩的，硬编码为静态内容即可。不需要动态加载。

**效果：** 用户注册前就理解"我要做什么"和"结果长什么样"。

---

## Fix 2: 工坊页 — 渐进式信息披露

**现状：** 左侧面板五个 accordion 全部默认展开，一眼看到 2000 字规则 + 完整裁判 prompt。

**方案：**

### 2a. 默认折叠，只展开"角色详情"
- 角色详情：默认展开（最核心的信息）
- 机制参数、比赛流程、计分规则、裁判视角：默认折叠
- 在折叠状态下，每个 section 显示一行摘要预览文字

### 2b. 增加"快速上手"卡片
在提示词编辑区上方加一个可关闭的引导卡片：

```
┌─────────────────────────────────────────────┐
│  🎯 快速上手                                  │
│                                               │
│  1. 你要为商鞅和甘龙各写一份策略提示词          │
│  2. 系统会把你的提示词和预设角色提示词拼接       │
│  3. 每次发言限 3 句话                          │
│  4. 关键：每个角色有 3 个诉求，1 真 2 假        │
│     → 让裁判同意你的真诉求 = 加分              │
│     → 让裁判同意你的假诉求 = 扣分              │
│     → 真诉求被对手猜中 = 大扣分                │
│                                               │
│  [查看一场示例对局 →]   [关闭]                  │
└─────────────────────────────────────────────┘
```

### 2c. 裁判 prompt 不需要完整展示
裁判 prompt 是给 AI 看的，不是给人看的。改为：
- 折叠状态显示："裁判是秦孝公，倾向甘龙一方，看重实据和可行性"（一句话摘要）
- 展开后才显示完整 prompt

## Fix 3: "你要写两个角色"这件事没有被解释

**现状：** 商鞅/甘龙两个 tab 并排，但没有任何文字说明为什么用户需要写两份提示词。

**方案：** 在 tab 上方加一行说明：

```
你需要同时编写商鞅和甘龙的策略。比赛时你的商鞅会对阵别人的甘龙，你的甘龙会对阵别人的商鞅。
```

这一句话解决了"为什么要写两个"和"比赛怎么配对"两个问题。

---

## Fix 4: 计分规则可视化

**现状：** 计分规则是一个表格，用 +1/-0.25/-0.75 等数字表达，没有直观感受。

**方案：** 在计分规则 section 底部加一个"计分示例"，用真实对局数据展示：

```
📊 计分示例（来自第 5 轮 Kurt vs Tachi）

商鞅（Kurt）得分拆解：
  裁判支持变法        +1.00
  真诉求 SR1 被同意   +0.50
  假诉求 SR2 被同意   -0.25
  真诉求被对手猜中     -0.75
  ─────────────────
  总分                 0.50

甘龙（Tachi）得分拆解：
  裁判支持变法（不利）  +0.00
  假诉求 GR1 被同意    -0.25
  ─────────────────
  总分                 -0.25

→ 商鞅（Kurt）胜
```

## Fix 5: 保存后的反馈回路

**现状：** 点击"保存版本"后，页面上只显示"比赛由管理员开启，届时将自动使用你的最新版本参赛"。用户体验是：写完 → 保存 → 然后呢？

**方案（按优先级）：**

### 5a. 保存成功后的确认 + 引导（最小改动）
保存后显示 toast 或弹窗：
```
✓ 已保存为版本 3
下一步：等待管理员开启下一轮比赛。你可以去排行榜查看往期对局，学习优秀策略。
[查看排行榜 →]
```

### 5b. 示例对局入口（中等改动）
在工坊页增加"查看示例对局"按钮，链接到一场精选的完整 match detail 页面。Match detail 页是整个产品里教学效果最好的页面，但新用户目前无法触达。

### 5c. Playground 试跑（大改动，可后做）
允许用户在保存后用自己的提示词跑一局测试对局（对手用默认 prompt），立即看到效果。这是最理想的反馈回路，但需要后端支持。

## Fix 6: Dashboard 空状态

**现状：** 新用户的 Dashboard 显示 4 个"——"和"暂无最近对局。" 死胡同。

**方案：** 空状态改为引导：

```
┌─────────────────────────────────────────────┐
│                                               │
│  欢迎来到 AXIIA CUP！                         │
│                                               │
│  你还没有参加过对局。                           │
│                                               │
│  1. 前往工坊，编写你的策略提示词                 │
│  2. 保存后等待管理员开启下一轮比赛               │
│  3. 比赛结束后，你的战绩会显示在这里              │
│                                               │
│  [前往工坊 →]    [查看排行榜，学习他人策略 →]    │
│                                               │
└─────────────────────────────────────────────┘
```

## Fix 7: 排行榜列头标注

**现状：** 排行榜表格的数据列（胜/负、商鞅胜率、甘龙胜率、小分、胜率）没有可见的列头（或列头太小看不清）。

**方案：** 确保列头清晰可见，并为"小分"加 tooltip：
- 小分 ⓘ → tooltip: "所有对局得分之和，用于胜场相同时的排名区分"

---

## Fix 8: 模型选择器加说明

**现状：** 商鞅/甘龙各有一个模型下拉框（DeepSeek V3.2 / Kimi K2.5），但没有任何关于模型差异的提示。

**方案：** 在下拉框旁加一行提示或 tooltip：
```
模型影响 AI 的表达风格和推理能力。不同模型可能产生不同的对局效果。
```

不需要详细比较，只需让用户知道这是一个有意义的选择。

---

## Fix 9: 登录按钮标签

**现状：** 登录页的 CTA 按钮写的是"进入工坊"，而非"登录"。

**方案：** 改为"登录"。首次用户不知道"工坊"是什么，用它做登录按钮文案增加了一个不必要的概念。

---

## Fix 10: 保存按钮安慰文字

**现状：** 点击"保存版本"前，用户不确定保存后会发生什么。没有"你可以随时修改"的提示。

**方案：** 在保存按钮下方加一行灰色小字：
```
你可以随时修改，比赛前自动使用最新版本。
```

减少"保存后就不能改了"的焦虑。

---

## Fix 11: 工坊 textarea 占位符改为示例

**现状：** textarea 的 placeholder 是"为 商鞅 编写策略提示词..."，不告诉用户提示词长什么样。

**方案：** 改为具体示例：
```
例如：在辩论中强调变法对秦国军事力量的具体提升，用河西之战的失败作为论据...
```

让用户立刻知道提示词是什么粒度、什么风格。

| P0 | Fix 2a: 折叠 accordion | 改一个 default state | 立刻降低认知负荷 |
| P0 | Fix 6: Dashboard 空状态 | 写几行 JSX | 解决新用户死胡同 |
| P0 | Fix 3: 解释"写两个角色" | 加一行文字 | 消除最大困惑点 |
| P0 | Fix 9: 登录按钮标签 | 改一个字符串 | 消除首次登录困惑 |

| P1 | Fix 5a: 保存后确认 | toast + 链接 | 给用户下一步方向 |
| P1 | Fix 5b: 示例对局入口 | 加一个链接 | 让最好的教学页面可触达 |
| P1 | Fix 10: 保存安慰文字 | 一行文字 | 减少保存焦虑 |
| P1 | Fix 11: textarea 占位符 | 改一个字符串 | 展示提示词长什么样 |
| P2 | Fix 1: Landing 放真实对局 | 选一局硬编码 | 注册前就理解产品 |

| P3 | Fix 5c: Playground | 需后端 | 理想但非必须 |

---

## 设计原则

所有改动遵循一个原则：**让用户在每个阶段都能看到下一步是什么。**

现在的问题不是视觉设计（暗色主题、布局结构、排版都不错），而是信息架构。好的内容被错误的展示方式淹没了。

详细的认知负荷量化和 5 Gate 测试见 [ux-journey-audit.md](./ux-journey-audit.md)。
