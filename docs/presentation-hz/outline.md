# Axiia Cup 杭州国美 Vibe Coding 课程分享 Outline

## 分享主题

这次分享会围绕 Axiia Cup 展开。Axiia Cup 是一个智能体对抗大赛：参赛者不是写代码，而是写 prompt，让大模型扮演不同角色，在历史、哲学和伦理场景里进行辩论、说服和博弈。

我会结合这个项目，介绍一个 AI-native 产品是怎么从一个想法，逐步变成场景、规则、prompt、对战系统、裁判机制和真实可玩的网页产品的。

## 1. Axiia Cup 是什么

我会先介绍 Axiia Cup 的基本形态：

- 玩家写策略 prompt，控制 AI agent 的行为。
- 两个 agent 会在同一个场景中对抗。
- 玩家可以选择不同的大模型来驱动自己的 agent。
- 对战结束后，会由另一个大模型担任裁判，给出判决和结果。
- 比赛的核心不是写一段漂亮的话，而是设计一个能在规则、裁判偏好和对手策略中取胜的智能体。

## 2. 现场体验 Axiia Cup

在正式讲规则之前，我会先请大家登录 Axiia Cup 网站，自己选择一个场景，随手写一些 prompt，尝试跑一局游戏。

可以选择的场景包括：

- 商鞅变法
- 本能寺之变
- 电车难题

这个环节的目的，是让大家先直接感受到：prompt 不是静态文本，它会变成 agent 在对话中的行为方式。

## 3. Axiia Cup 的开发历程

之后我会讲 Axiia Cup 是怎么被做出来的。

一开始的问题是：能不能把 prompt writing 做成一种真正有胜负、有策略、有迭代空间的比赛？

从这个问题出发，项目逐渐发展出几个核心方向：

- 把 prompt 从“写给模型的指令”变成“控制 agent 的策略”。
- 把单次聊天变成多轮对抗。
- 把历史、哲学、伦理场景设计成可以比赛的规则系统。
- 把大模型同时用作玩家 agent、裁判和评分系统。
- 通过 Vibe Coding、Codex、Claude Code 等工具，把这些设计快速落地成真实产品。

这里我会重点讲两个部分：场景设计和程序开发。

场景设计主要关注：什么样的题材适合变成 agent 对抗？角色之间要有什么冲突？裁判应该是谁？规则怎样才能既容易上手，又有策略深度？

程序开发主要关注：如何把玩家 prompt、角色信息、隐藏目标、对话历史、裁判 prompt 和评分逻辑组织起来，让整场比赛可以稳定运行。

## 4. 三个主要场景

### 商鞅变法

这是一个历史辩论场景。

商鞅主张变法，甘龙主张维持现状。两方在秦孝公面前进行朝堂辩论。秦孝公听完之后，会决定是否支持变法，也会判断双方提出的请求是否合理。

这个场景里，玩家要做的不只是替商鞅或甘龙说话，还要读懂秦孝公这个裁判：他看重什么，他害怕什么，他会被什么样的论证说服。

### 本能寺之变

这是一个围绕明智光秀决断的历史场景。

天正十年六月一日深夜，明智光秀即将出兵。信长人在本能寺，护卫很少。此时光秀面前的核心问题是：应该袭击本能寺，还是继续按原命令西进？

两方会从不同角度劝说明智光秀。有的角色主张杀信长，有的角色主张不要行动。这里的关键不是“历史后来发生了什么”，而是在那个夜晚的处境里，什么理由足以推动一个人做出不可逆的选择。

### 电车难题

这是一个哲学和伦理场景。

两方分别代表“一人侧”和“五人侧”，围绕多个电车难题变体进行辩论。每个案件都要求在一人承受伤害和五人承受伤害之间做选择。

这里没有历史角色，也没有隐藏身份。重点变成了原则本身：一个立场能不能跨不同案件保持一致？辩手能不能解释清楚案件之间真正重要的差别？

## 5. Judge Prompt 为什么公开

我会特别介绍 Axiia Cup 里一个很重要的设计：judge prompt 是公开的。

裁判不是一个神秘黑箱。玩家可以看到裁判是谁、裁判在意什么、裁判会怎样判断一场对话。

这会改变比赛的性质。玩家不是在盲目讨好一个不可见的模型，而是在研究一个公开的评价系统，并据此优化自己的 agent prompt。

以商鞅变法为例，秦孝公不是一个完全中立的评分机器。他有自己的性格、利益和风险偏好。他看重实据、利害和可行性，也担心宗室反弹。好的 prompt 会针对这个裁判设计策略，而不是只写一段历史上“听起来正确”的发言。

这也是 Axiia Cup 最有意思的地方之一：比赛表面上是两个 agent 在对话，实际上玩家是在读规则、读裁判、读模型。

## 7. Judge Bias Spectrum

最后我会简单介绍 Judge Bias Spectrum：

https://judge-bias-spectrum.vercel.app/

这个页面展示的是：同一批对战记录，如果换不同的大模型来当裁判，判决会发生怎样的变化。

这说明 LLM 裁判并不是完全中性的。不同模型会有不同偏好，有的更偏向改革，有的更偏向稳定，有的更重视论证风格，有的更重视请求是否被满足。

这也是 Axiia Cup 从一个游戏延伸出来的更大问题：当我们让 AI 来评价人类语言和策略时，我们到底是在使用一个客观裁判，还是在使用一个带有模型偏好的评价者？
