Judge Reacts in Real-Time

3-way dialogue Info/Facts Silence ≠ optimal

  • Directly solves silence problem via utility
  • Avalon-like "use but risk exposure" tension
  • Elegant, easy to explain

  • Needs 3-way conversation engine (doesn't exist)

Hidden Sub-Goals Active

No engine change Sub-Goals Narrow x range
+
  • Narratively natural: "商鞅有些小心思"

  • Compatible with current architecture

C

Observable Anomaly + Hidden Goals

Yihan (Apr 3–4) • Theater model
Scenario creates observable anomalies (e.g., "Why are you home early?") that force agents to address their hidden situation. Hidden goals from randomized pool of N. 3D evaluation: public goal + hidden goal achieved + hidden goal undetected.
Structural forcing Goals Heavy design load
+
  • Forcing is structural, not gameable by scoring
  • Richer game: coherence + stealth + persuasion
  • Generalizes to any scenario
−
  • Heavy scenario author burden (anomalies + N goals)
  • "Goal achieved?" is subjective LLM judgment
  • Anomaly quality depends on author skill
  • Missing formal game theory proof

  • Massive scope: rumor engine + objection engine + cost logic

The Four Required Dimensions (from discussion)

All four must be present for hidden info to create good gameplay. Missing any one breaks the game.

1. Forcing Observable Anomaly

Hidden info causes something visible that demands explanation. Without it, silence is optimal.

A: Judge Reacts Utility-driven
B: Sub-Goals Score-driven (narrow range)
C: Anomaly Structural
D: Rumors Direct question
E: Pure Debate None
F: Post-Game Only public demand

2. Utility Info helps achieve goal

True hidden info helps you win. Without it, no reason to use it even when forced.

A: Judge Reacts Judge reacts positively
B: Sub-Goals +0.5 for approval
C: Anomaly Goal = bonus scoring
D: Rumors Truth = trust gain
E: Pure Debate N/A
F: Post-Game None (info is liability)

3. Exposure Risk Use it = signal it

Using the info creates detectable signals. Without it, always use = dominant.

A: Judge Reacts Opponent reads reactions
B: Sub-Goals Pushing goal = signal
C: Anomaly Behavioral tells
D: Rumors Response quality = signal
E: Pure Debate N/A
F: Post-Game Only if discussed

4. Opponent Interaction Reason to probe

Opponent has incentive + mechanism to detect your hidden info. Without it, single-player puzzle.

A: Judge Reacts Watch judge's reactions
B: Sub-Goals Guess = points
C: Anomaly Detection = bonus
D: Rumors Objection system
E: Pure Debate None
F: Post-Game Guess only post-game

Simon's Game Theory Analysis (math.md)

From kesouuuu/axiia-cup-problems/scratchpad/math.md

Setup (Option B)
Major objective: winner +1 • True sub-goal approved: +0.5 • Opponent detects true: −1 • False approved: −x • Approval probability: p

Strategy Expected Scores (sub-goals only)

StrategyFormulap=0.7, x=0.25p=0.7, x=0.35
Silence (push nothing)-1/3−0.33−0.33
Push true only0.5p - 1−0.65−0.65
Push true + 1 false0.5p - xp - 0.5−0.325 ☆−0.395
Push all 30.5p - 2xp - 1/3−0.33−0.47

☆ Only "true + 1 false" beats silence, and only barely (−0.325 vs −0.33)

Critical Constraint
For "true + 1 false" to beat silence: p(0.5 - x) > 1/6
When p = 0.7: requires 0.243 < x < 0.262

This is an extremely narrow valid range! The entire mechanism's incentive structure depends on hitting a ~0.02-wide window for the false-goal penalty parameter.

Dependent vs Independent Sub-Goals

Independent: Don't need major objective win. E_i = p_a × r_i
Dependent: Need major win first. E_d = p_b × p_a × r_d

When p_b = 0.5, equivalence requires r_d = 2 × r_i = 1.0
This means dependent sub-goals must be worth as much as the entire major objective, which distorts incentives.

Simon's Open Problems

  • "Push all 3" twist: If false penalty is low enough, pushing everything is dominant. Two proposed fixes: (1) penalty tuning, (2) token/turn scarcity
  • Narrow x range: The mechanism is fragile. Small changes in approval probability p shift the optimal strategy
  • Dependent goals need 2× reward: Creates pressure asymmetry between players who roll dependent vs independent goals
  • Need all sub-goals in same category: Mixing dependent/independent in the same pool creates unfairness

Test Plan: How to Validate Each Option

1. Paper Simulation

Write 2-3 hidden info/goal assignments. Have humans (or Claude) play both sides with different strategies. Score manually.

Measures:
  • Does silence actually win? (strategy dominance)
  • Do intended incentives hold?
  • Is the game "fun" / interesting?
Low effort • 1-2 hours • Can do now

2. LLM A/B Test

Run matches with same prompts under different mechanisms (B vs F vs E). Compare outputs quantitatively.

Measures:
  • Does hidden info get discussed? (count references)
  • Is opponent guessing > 33% accuracy?
  • Score variance (skill differentiation)
Medium effort • Need API calls • Script ~2h

3. Parameter Sweep (for Option B)

Sweep (p, x) space programmatically. Plot which strategy dominates at each point. Validate Simon's narrow-range finding.

Measures:
  • Exact valid range for x at different p values
  • Robustness: how much does p need to shift to break it?
  • Try N=2,3,4 sub-goals
Low effort • Pure math / Python • ~1h

4. Strategy Dominance Check

For each option: one AI plays "always silent", another plays "optimally". If silence wins or ties, mechanism fails.

Measures:
  • Silence win rate (must be < 40%)
  • Optimal vs silence margin
  • Is there a single dominant strategy?
Medium effort • ~10 matches per option • ~3h API time

5. Judge Variance Test

Run same transcript through judge 10×. Measure agreement rate for subjective evaluations.

Measures:
  • Agreement rate (target: >80%)
  • Score standard deviation
  • Binary decisions (B, F) vs subjective (A, C, E)
Low effort • 10 API calls per transcript • ~30min

6. Live Playtest (Apr 8 MVP)

15 people play Option E (pure debate). Collect baseline data. Then in a follow-up session, try Option B or F layered on.

Measures:
  • Engagement (qualitative feedback)
  • Score distribution (normal? bimodal?)
  • Do players feel prompt skill matters?
  • Would hidden info make it more fun?
High effort • Needs full system running • Apr 8 event

Recommended Phased Testing

Phase 1: Apr 5-7 (Before MVP) Test 3 + Test 5: Parameter sweep for Option B math, judge variance test on sample transcripts. Low effort, high signal.
Phase 2: Apr 8 (MVP Day) Test 6: Live playtest with Option E. Collect baseline engagement data and qualitative feedback.
Phase 3: Apr 9-30 (Post-MVP) Tests 1, 2, 4: Paper simulation, LLM A/B test, strategy dominance check. Compare B vs C vs D. Pick winner for May competition.
