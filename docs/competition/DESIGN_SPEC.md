## 1. 产品概述

**产品名称：** Axiia Cup（AA Cup）

**一句话：** 玩家为特定场景和角色侧创建 AI 智能体，通过提示词与模型选择，让智能体在人文学科场景中进行对抗性对话。

**竞技对象：** 比赛衡量玩家的**提示词设计 + 模型使用技巧**，而不是让玩家自建工具链。

**目标用户：** 中国初高中及大学生。

**能力边界：** 玩家提交纯文本提示词并选择平台提供的模型；禁止 RAG、工具调用、多轮链和函数调用。

**Alpha 核心闭环：**

```text
选场景 → 为一个角色侧构建智能体 → 对战 → 阅读战报 → 学习 → 迭代版本
```

### 1.1 产品定位差异

**相比狼人杀 AI 大赛：**

- Axiia Cup 使用更简单的 1v1 结构，降低 token 成本并提高竞技信号的可解释性；
- 衡量人类玩家的策略设计能力，而不是模型本身；
- 聚焦人文学科与教育场景。

**相比工具型 Agent / 工作流大赛：**

- 工具型比赛衡量 agent 能完成什么外部任务；
- Axiia Cup 衡量玩家能否设计有效的对抗性对话策略；
- 玩家不能通过自建工作流、工具或 RAG 扩展 agent 能力。

## 2. 核心概念

### 2.1 Agent、侧与版本

- 一个 **agent 只属于一个场景中的一个角色侧**，例如“商鞅「破局者」· 商鞅变法”。
- 一个版本是该单侧 agent 的不可变快照：**单侧提示词 + 所选模型**。
- 玩家在同一场景的每一侧都可创建多个 agent。
- 创建同侧第二个 agent 前，玩家必须在同一场景中拥有至少一个**现存的对侧 agent**；迭代已有 agent 的版本不受此限制。
- 上述引导门按“玩家 × 场景”隔离。删除最后一个对侧 agent 后，引导门重新生效。
- 系统在“我的智能体”、EA 智能体页、构建器及参赛入口显示双侧完成度，例如“商鞅 ✓ / 甘龙 ✗”，并在缺侧时引导创建对侧。
- 每个单侧版本都有可分享、可解析的版本 ID。
- **参赛版本按侧显式标记**：参加一个场景的锦标赛时，每侧必须各标一个版本；只完成一侧不能参赛。

### 2.2 PVE-NPC

- **PVE-NPC** 是团队按场景配置的官方对手。
- 每场景默认提供 2 个，数量可配置。
- NPC 的具体提示词、难度排序和场景台词属于场景内容。
- NPC 展示的战绩是该场景两个角色侧的 agent 胜率，不是某位玩家的胜率。

### 2.3 内心 OS

内心 OS 必须存在，分为三种数据：

1. **玩家 agent trace**：玩家所用模型的真实 thinking/reasoning trace；默认隐藏，仅该 agent 所有者可在 debug mode 查看。
2. **裁判 OS 生成层**：使用独立 prompt、裁判人设与裁判模型生成；默认显示，对所有观众公开；同时输出结构化倾向数据，作为回放教学锚点。
3. **裁判真实 trace**：裁判模型的真实 thinking/reasoning trace；在 debug mode 中对所有观众公开。

PVE-NPC 由官方运行，其 trace 视为系统侧数据，与裁判真实 trace 一样在 debug mode 中公开。

### 2.4 战报与派发

- **战报（FA）**是赛事、PVP、PVE 的唯一对局视图，覆盖排队、进行中和完成三态。
- 除首战外，对战采用异步派发。玩家可离开派发处，稍后从“进行中的对战”条、通知或历史页进入战报。
- 首战是例外：保存后自动派发并直接进入实况。

## 3. 用户流程与信息架构

### 3.1 主路径

```text
D 场景选择 → DA 场景介绍 → E 构建器 → 保存 → OS 选择对手 → 派发 → FA 战报
                                         ↘ EA 智能体页（可选，不在主路径）
```

全局导航为：

```text
场景 · 我的智能体 · 排名 · 历史 · 通知 · 设置
```

- “我的智能体”按场景分组列出全部 agent，并显示双侧完成度。
- 通知以全局铃铛呈现并显示未读数。
- 桌面顶栏与移动底栏保持相同的信息架构。
- Sub-page 是可独立设计、复用和平铺的页面组件；未来的 Focus mode 建立在这一结构上。

### 3.2 首战快速通道

新用户使用邀请码注册并自动登录后进入快速通道：

1. 查看简化版场景介绍。
2. 进入 express 构建器；默认使用 MCQ 和预填模板，也可切换正常构建方式。
3. 创建一个由配置指定角色侧的单侧 agent。
4. 保存后自动对战配置中“最容易”的 PVE-NPC，并直接进入实况。
5. 完成后在战报底部展示带方向性 CTA 的首战引导，并展示三种构建模式入口。
6. 引导玩家创建对侧 agent，继续 PVE 和 PVP 解锁流程。

首战优先优化“开始第一场对局所需时间”；是否使用更低轮数缩短整场时间仍是场景或后续设计决定。

### 3.3 进行中的对战条

- 只在有派发能力的上下文出现，展示玩家发起的排队中、进行中和刚完成对局。
- 空态自动隐藏，可折叠；移动端横向滚动。
- 点击对局卡可打开侧抽屉观战，并可进入完整战报。
- 完整记录统一进入“历史”页。

## 4. 场景系统

### 4.1 系统要求的场景数据

场景接口和配置至少支持：

| 层级 | 内容 |
|------|------|
| 基础 | 名称、学科、一句话介绍、背景、难度、适合新手标注、预计时长、上线时间 |
| 角色 | 两侧角色卡、公开要求、行动重点、胜利条件、边界约束、可选立场/请求项、开场白 |
| 对局 | 对话轮数、阶段结构、隐藏信息真假配置概况、赛后问询方式 |
| 裁判 | 裁判人设、公开裁判 prompt 及摘要、评判维度、精确权重、裁判与计分模型 |
| 构建 | 两侧 MCQ deck、系统角色模板、PVE-NPC 列表 |

`judgeOsPrompt` 仅供管理员维护，不下发到玩家侧。

对话轮数由场景作者配置，范围为 10–20 轮，默认 20 轮。

### 4.2 D — 场景选择

- 每个场景使用一张卡片，展示一句话介绍、难度、适合新手标注、预计时长和两侧胜率。
- 难度为“简单 / 中等 / 困难”；“适合新手”是独立标注。
- 统计只有在达到可配置的对局数门槛后才显示，不以胜率作为展示门槛。
- 最近上线的场景固定在列表第 2 位，并显示“新上线”徽章。
- 新场景未达到统计门槛时显示引导式空态轮廓，不显示无意义的空数字。
- “最热门”动态精选属于未来功能。

### 4.3 DA — 场景介绍

- DA 是独立教育页面，与构建器 E 分开。
- 使用 GLANCE → EXPAND-1 → EXPAND-2 → DEEP 四层渐进展示。
- 保留“叙事呈现 ↔ 原始规则”的切换。
- GLANCE 层必须展示两侧胜率。
- 页面公开：背景、双方身份与胜利条件、裁判 prompt 及摘要、评判内容、隐藏目标玩法、计分规则、预计时长。
- EXPAND-1 增加双方可选立场/请求项与开场白。
- EXPAND-2 增加隐藏信息真假配置概况、赛后问询方式、对话轮数与阶段结构。
- DEEP 增加裁判模型与计分模型。
- 隐藏目标对人公开、对对手 agent 隐藏；每局具体随机分配属于场景内容。
- 计分规则必须来自场景数据，不得在前端硬编码；精确权重全部公开。

### 4.4 场景内容边界

以下内容由场景作者或场景配置决定，本文只约束系统支持能力：

- 角色卡、系统角色模板、裁判人设及提示词；
- 隐藏信息的真假配置与每局随机分配；
- 对话轮数、阶段结构和赛后问询内容；
- 计分权重、惩罚值与具体计分脚本；
- 结构化计分或 LLM 散文给分的选择；
- MCQ deck 的题目与提示词片段；
- NPC 的提示词、难度排序与场景台词。

系统必须同时支持结构化计分和 LLM 软判断，并在战报中如实展示实际采用的推导过程。

## 5. 智能体构建器

### 5.1 E — 构建器

- E 是绑定场景的独立页面，包含紧凑、可折叠的场景资料栏。
- 三种构建模式都生成同一种结果：不超过上限的单侧纯文本提示词。
  1. **MCQ**：默认模式；全场景可用；用文本选择题拼装提示词。
  2. **Basic**：直接编写提示词。
  3. **Prompt-builder prompt**：提供元提示词，让玩家带到自己的 AI 中使用；产品内不提供聊天。
- 每个版本的提示词上限为 **1000 个单位**，按汉字或英文词计，不按 token 计。
- 模型选择器是明确控件；模型属于版本快照；可选模型清单由配置下发。
- 保存只创建新版本，不自动派发；首战快速通道是唯一例外。
- 编辑已有版本时必须另存为新版本，不覆盖历史快照。
- 页面固定说明：“你只需编写策略；比赛时系统自动与角色模板合并”。系统角色模板可展开只读查看，并标明“仅供查看，无需重复”。
- 构建器不提供对局预览或快速测试；测试统一通过 PVE/hotseat 完成。
- 未完成的控件不得在 Alpha UI 中出现。

### 5.2 EA — 智能体页

- 展示名格式为“侧角色名「自起名」· 场景”。
- 所有者可查看提示词、版本 diff、逐版本战绩、版本 ID 和参赛版本标记。
- 页头“编辑”载入最新版本；版本卡“编辑此版本”载入指定版本；两者保存时都另存新版本。
- 公开访问者可查看逐版本战绩，但永远不能查看提示词或 diff。
- EA 显示双侧完成度并在缺侧时提供创建入口。
- PVE-NPC 的 EA 视图使用聚合数据，并展示该场景两侧 agent 的胜率。
- EA 可从排行榜、构建保存结果、我的智能体、玩家对局列表及战报中的双方入口进入。

## 6. 练习、PVP 与派发

### 6.1 PVE

- 玩家选择一个单侧 agent 出战；更换角色侧等同于改选另一侧 agent。
- PVE 对手为当前场景的 PVE-NPC。
- 系统记录“玩家 × 场景 × 侧 × NPC”的首次胜利事实，用于 PVP 解锁。
- 同一 NPC 的重复胜利在同一侧只计一次解锁进度。
- PVE 不设独立的重复对局上限，但仍计入每日总对战次数。

### 6.2 Hotseat 自打

- 玩家可以让自己的一个 agent 对战自己对侧的 agent；对侧有多个 agent 时必须明确选择。
- 两侧 agent 在手即可使用，不受 PVP 解锁门槛限制。
- Hotseat 不占 PVP 配额，但占每日总对战配额。
- Hotseat 不计天梯，也不计 PVE-NPC 解锁进度。
- Hotseat 不设独立的重复对局上限。

### 6.3 OS — 选择对手

- OS 是从 agent 呼出的紧凑派发面板；预选 agent 和版本，执方由 agent 所属侧隐含。
- 切换角色侧等同于切换到另一侧 agent；若不存在则引导创建。
- 面板包含：PVE、PVP 按版本 ID、PVP 顶尖玩家、自动匹配（计分）及 hotseat。
- PVP 未解锁时相关 tab 保持可见但锁定，并展示分侧进度。
- “顶尖玩家”的排序及自动匹配完整机制属于天梯工作项。
- 移动端使用底部弹层；派发后的对战条可横向滚动。

### 6.4 PVP 友谊赛

- 手动约战不计天梯分。
- 一次约战产生两场独立对局：我方 A vs 对方 B，以及对方 A vs 我方 B。
- 发起方和被约方都必须双侧齐备，并且都已达到当前场景的 PVP 解锁门槛。
- 对方收到站内通知，无需同意且不能拒绝。
- 默认使用双方各侧的最新版本；可通过版本 ID 指定版本。另一侧版本如何补全见“待完成工作”。
- 两场各有独立战报，并保留同一约战的关联关系。
- 一次约战按两场计入发起人的配额；剩余额度不足两场时整对拒绝。
- 被约方不消耗每日次数。
- **完全重复约战**按双方阵容判定：发起方两侧与被约方两侧所选的 agent-version 组合均与此前约战相同，才算一次完全重复。
- 同一完全重复阵容每天最多发起 X 次，X 可配置；达到上限后拒绝整对约战，避免浪费每日对局数。
- 只要任一方改用不同的 agent-version 组合，就不受上述完全重复上限；即使仍是同一对手玩家，也只受每日总对战次数、PVP 每日次数和并发上限约束。

### 6.5 限额与阻挡

- 每玩家每日总对战次数、PVP 每日次数和并发数均可配置。
- 触顶时按钮仍可点击；系统返回“今日次数已用完（N/N），明天再来”并拒绝入队。
- 赛事运行期间，运营可以阻挡全部试炼。
- Alpha 不要求裁判反 prompt-injection 防护；允许玩家探索注入策略。

## 7. 门槛、排名与锦标赛

### 7.1 进阶闭环

```text
两侧各建 agent 并打 PVE
→ 每侧击败至少 N 个不同 PVE-NPC
→ 解锁当前场景 PVP
→ 手动友谊赛 / 自动匹配计分
→ 每侧显式标记一个参赛版本
→ 参加锦标赛
```

- PVP 门槛按“玩家 × 场景”分别计算。
- 默认每侧需击败至少 1 个不同 PVE-NPC；阈值 N 可配置且不得大于每场景 NPC 数。
- 门槛与排名是不同系统；PVE 不为天梯播种分数。

### 7.2 天梯

- 自动匹配 PVP 计分，完整匹配算法、分数模型和防刷机制仍待专门评审。
- 天梯初始为 0/空，只根据真实 PVP 或锦标赛结果更新。
- 天梯、排名和资格记录全部按“玩家 × 场景”记录，不按单个 agent 或角色侧建立独立排名。
- 模型选择不构成天梯分组依据；所有玩家面对同一可配置模型清单。

### 7.3 锦标赛 / 排名中心

- 排名中心包含锦标赛与天梯两个视图。
- 锦标赛视图支持赛事选择器和按轮时间线。
- 报名时校验当前场景两侧参赛版本是否齐备。
- 玩家在某场景拥有至少一个达到高分门槛的 agent 后，获得“玩家 × 该场景”的锦标赛资格，包括后续赛事直邀或跳过海选资格。
- 高分 agent 只是触发资格的证据，不是资格主体；资格不跨场景迁移。
- 获得资格后，玩家不必使用触发资格的 agent 参赛，可另选该场景两侧各一个符合要求的参赛版本。
- “高分”的计算方法和门槛属于天梯设计工作项。

## 8. 对局与战报

### 8.1 对局状态

战报统一呈现三态：

| 状态 | 含义 |
|------|------|
| 排队 | 已接收请求，等待执行 |
| 进行中 | 对话或裁判流程正在运行，可观看实况 |
| 完成 | 结果、对话、问询、隐藏目标和计分推导可查看 |

赛事、PVP、PVE 使用同一套状态和战报数据结构。

F（Battleground）不是独立页面，而是战报加发起者可用的运行控制；具体控制项仍待定义。

### 8.2 完局信息顺序

```text
结果（胜者 + 分数）
→ 完整对话
→ 赛后问询
→ 隐藏目标五步结构
→ 计分推导
```

隐藏目标五步结构为：真目标 → 辩论中是否达成 → 对手猜了什么 → 是否被识破 → 得分变化。

战报还必须展示：

- 双方模型和双方单侧版本 ID；
- 裁判散文理由；
- 结构化计分维度、精确权重和 LLM 软判断；
- 我方显眼的“← 我的智能体”入口；
- 对手侧低调的“查看对手智能体”入口。

### 8.3 可见性

受限信息只有三类：

1. 玩家提示词：仅所有者；
2. 版本 diff：仅所有者；
3. 玩家 agent 的真实 trace：仅所有者在 debug mode 查看。

其余内容——对话、结果、分数、裁判 OS 两层、PVE-NPC trace、模型和版本 ID——对所有观众公开。访问控制必须由服务端过滤，不能只靠前端隐藏。

因此，对手及其他玩家的提示词始终不可见；只有提示词所有者本人可以读取。

### 8.4 回放与分享

- 战报可通过链接分享，无需额外隐藏信息打码。
- 回放不产生新的 LLM 调用，而是从既有数据将内容从 0 到终局动态重演。
- 回放以裁判结构化倾向变化为教学锚点。
- 回放进行中隐藏 debug/trace 层；回放是公开教学层。
- 除首战实况外，发起对战不强制打开新窗口或自动滚动页面。

## 9. 裁判与计分

### 9.1 系统规则

- 裁判是场景内角色，而不是脱离叙事的抽象评分器。
- DA 向玩家公开裁判 prompt、摘要、评判维度和精确权重。
- `judgeOsPrompt` 不公开，仅由管理员维护。
- 系统支持结构化计分和 LLM 散文给分；场景可选择使用哪一种或组合使用。
- LLM 软判断必须如实展示，不能伪装成客观规则。
- 裁判 OS 生成层必须同步产出结构化倾向数据，供实况和回放使用。
- 裁判真实 trace 与独立生成的裁判 OS 同时保留，二者不能互相替代。
- 裁判 prompt 必须版本化；每次平衡更新公开发布变更说明，并通过系统公告通知玩家。

### 9.2 战报中的裁判数据

- 独立生成的裁判 OS 默认公开显示。
- 裁判真实 trace 在 debug mode 中公开。
- 精确权重、双方得分、判断说明和最终推导全部公开。
- 具体计分数值、场景脚本和隐藏目标配置属于场景内容。

## 10. 首页、通知、设置与历史

### 10.1 首页

公开首页无需登录即可访问，可展示真实对局节选、1–2 场白名单示范对局、顶尖玩家和总对战数。示范对局遵守战报的公开可见性规则。

### 10.2 登录与注册

- Alpha 使用邮箱登录。
- 注册需要邀请码；成功后自动登录并进入快速通道。
- 手机号登录在接近公开上线时再加入。

### 10.3 站内通知

Alpha 只提供持久化站内通知。通知支持已读、清除、分组和深链，优先级为 PVP/锦标赛高于 PVE。

通知种类：

1. 玩家发起的 PVE/PVP 对局完成；
2. 被挑战；
3. 自动匹配结果与天梯变化；
4. 锦标赛新一轮、个人对局完成和最终排名；
5. 锦标赛直邀或跳过海选资格；
6. PVE 门槛达成、PVP 解锁；
7. 参赛版本锁定前提醒；
8. 系统公告，包括裁判 prompt 平衡更新。

派发响应提供 ETA，并提示“完成后通知你”。

### 10.4 设置与历史

- 设置页包含账户、邀请码状态、通知偏好和我的 agents；姓名隐私开关属于后续功能。
- 历史页列出完整对局记录，每行进入对应战报。

## 11. 配置注册表

全部配置使用文件 + CLI 管理，不做后台 UI；前端通过只读接口获得必要值，不得硬编码。

| 配置 | 作用域 | 当前规则 |
|------|--------|----------|
| 统计展示门槛 | 全局 | 按对局数，不按胜率 |
| 每日总对战次数 | 每玩家 | 只计发起人；触顶拒绝入队 |
| PVP 解锁门槛 | 每侧 | 默认击败 1 个不同 NPC |
| 每场景 PVE-NPC 数 | 全局默认 | 2 |
| 新手预设 | 全局 | 场景、执方、最容易 NPC |
| 模型清单 | 全局 | 随版本快照 |
| 可见性矩阵 | 全局 | 提示词、diff、玩家 trace 仅所有者 |
| 并发上限 | 每玩家 | 数值后定 |
| PVP 每日限次 | 每玩家 | 数值后定 |
| 完全重复约战上限 X | 发起人 × 双方四个单侧版本的组合 × 每日 | 相同阵容的成对约战最多 X 次 |
| 难度与新手标注 | 每场景 | 三档难度 + 独立新手标注 |

### 11.1 迁移与上线约束

- 赛事运行期间不部署 `submissions` 表迁移。
- 公开上线前完成 ICP 备案、服务条款和隐私页。
