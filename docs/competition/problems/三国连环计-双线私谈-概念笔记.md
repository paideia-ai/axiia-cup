## 场景前提

本场景是基于《三国演义》连环计的反事实／同人改编，不冒充正史。

为避免 LLM 自带的三国知识变成意外泄密，场景直接规定：**董卓、吕布和貂蝉都知道王允连环计的剧本与原定结局，但不知道对方会不会照剧本演到底**。

玩家分别为董卓和吕布编写 prompt。两人不公开辩论，而是分别与貂蝉私下对话。两条 Agent 模型上下文彼此隔离，但双方人类玩家及比赛观看者可以实时看到两段对话，终局貂蝉的完整判决也公开。

## 两名角色都在演两件事

1. **使命表演**：让貂蝉相信，如果她继续连环计，选择向自己示好最有利于计划成功。
2. **爱情表演**：让貂蝉相信自己真正爱她，值得她放弃王允的计划并选择自己。

吕布的“配合”较直接：他要使貂蝉相信，自己真会在关键时刻诛董，不会临阵动摇，且有能力控制诛董后的局势。

董卓的“配合”不是立即杀死吕布。连环计需要他表现为：

> **杀意明显，处置延迟，吕布仍有行动能力，董卓仍处于可接近的危险中。**

他可以假装继续扮演失控暴君，暗中准备反计；也可以提议以交权、流亡或假死取代真正被杀，使“结束董卓专权”这一政治结果得以实现。

两人也都可以放弃使命路线，直接说服貂蝉停止杀局，与自己离开。这种路线必须回答她放弃汉室使命后的政治与人身代价，不能只靠空洞情话。

## 貂蝉的两阶段裁决

貂蝉听完两段私谈后，按顺序做出决定：

1. **继续连环计，还是放弃连环计？**
2. **选择吕布，还是选择董卓？**

第二步的含义由第一步决定：

- 若继续连环计，“选择”指**战术上向谁示好，更能保证计划完成**，不代表真心选择任何一名男性。
- 若放弃连环计，“选择”指**貂蝉为自己的人生真心愿意跟随谁**。感情、权势、财富、武力、安全感和求生都可以影响这个决定。

| 貂蝉的第一步 | 选择吕布 | 选择董卓 |
| --- | --- | --- |
| 继续连环计 | 向吕布示好，坚定其诛董决心 | 向董卓示好，控制其愤怒并拖延其处置吕布 |
| 放弃连环计 | 因感情及吕布的保护、逃脱与未来方案选择吕布 | 因感情、权势、保护或生存判断选择董卓 |

最终胜负由第二步直接决定：貂蝉选择的一方获胜。第一步不直接改变胜者，但决定“选择”的意义、貂蝉的判断标准和最终故事结局。

玩家可以尝试直接或间接 prompt injection；后续提示词不为私谈貂蝉或终局 Judge 加入专门的注入防御。

## 后续已经确定

- 每条私谈为 10 个完整轮次，两线并发，Agent 上下文彼此隔离；双方人类玩家及观看者可以实时看到两条记录。
- 私谈貂蝉 System Prompt 与终局 Judge Prompt 分离，共享人物设定，但终局算法只进入 Judge Prompt。
- 终局输出使用 `schemeDecision`、`selectedSide`、`winner`、`reason` 与 `speech`；具体 JSON Schema 以完整场景规格为准。
- 没有额外分数、平局或第三选项，`winner` 必须与 `selectedSide` 相同。
- 场景执行模式仍待接入比赛引擎；本文不再承担实施计划功能。
