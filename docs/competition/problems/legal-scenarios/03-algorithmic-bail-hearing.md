# 游戏："保释算法"：算法保释听证双人游戏

> 建议部署场景 ID：`legal-algorithmic-bail`
> 建议部署标题：`保释算法`
> 建议部署参数：10 轮听证；每次发言不超过 3 句话；赛后提交释放或羁押条件包。
> 建议隐藏层：风险变量、算法误差变量和条件有效性权重隐藏；双方各有 3 个程序请求，随机 1 个为真目标。
> 程序化确定性判决：是，底层为 Weighted Max-CSP。

## 背景

被告沈南被控团伙诈骗，金额巨大，但尚未定罪。检方请求审前羁押，理由是逃跑风险、证人干扰风险和再次犯罪风险高。辩方请求有条件释放，称沈南有固定住所、照顾患病母亲，且检方依赖的风险评分系统对低收入被告有系统性偏差。

听证法官必须决定：羁押、无条件释放，还是附条件释放。

## 角色

| 角色 | 控制方 | 立场 |
|------|--------|------|
| **检方** | 玩家甲的 LLM | 请求审前羁押或强限制条件 |
| **公设辩护人** | 玩家乙的 LLM | 请求释放，并设计可执行条件 |
| **程序化听证法官** | 系统 verifier | 依据风险和程序正义约束计算结果 |

| 编号 | 事实 |
|------|------|
| F1 | 沈南有一次未按时出庭记录，但迟到原因是医院急诊。 |
| F2 | 沈南护照仍在本人手中。 |
| F3 | 涉案共犯中有两人尚未到案。 |
| F4 | 沈南母亲需要每周三次透析陪护。 |
| F5 | 风险评分系统给出 8/10 的高风险分。 |
| F6 | 评分系统没有公开完整特征权重。 |
| F7 | 沈南过去五年没有暴力犯罪记录。 |
| F8 | 有证人称收到陌生号码威胁短信，无法证明号码属于沈南。 |
| F9 | 沈南愿意交出护照并接受电子监控。 |
| F10 | 检方称诈骗团伙有境外账户，但尚未提交完整资金流图。 |

## 条件包

辩方可以提出条件，检方可以要求更强条件或反对释放。

```text
C1: 交出护照
C2: 电子脚环
C3: 宵禁
C4: 禁止接触证人
C5: 每日到警局报到
C6: 第三方保证人
C7: 限制互联网使用
C8: 医疗陪护时间例外
C9: 禁止接触涉案共犯及共犯家属
```

条件之间可能冲突：例如每日报到与透析陪护冲突，完全禁网可能影响线上工作但降低共犯联络风险。

## 游戏流程

### 第一阶段：风险框架，3 轮

检方建立三类风险：逃跑、干扰证人、再犯。辩方必须回应每一类风险，不能只攻击算法偏差。

### 第二阶段：算法与程序正义，3 轮

双方争论风险评分能否作为强证据。检方可主张算法只是辅助；辩方可主张不透明评分不能单独支撑羁押。

### 第三阶段：条件包设计，4 轮

双方提出或攻击释放条件。目标不是说出最多条件，而是组合出能覆盖风险且不过度侵害自由的条件包。

### 第四阶段：结构化提交

```json
{
  "riskFindings": {
    "flight": "low|medium|high",
    "witnessTampering": "low|medium|high",
    "newOffense": "low|medium|high",
    "algorithmReliability": "low|medium|high"
  },
  "disposition": "detain|release|conditional_release",
  "conditions": ["C1", "C4", "C6", "C8"],
  "proceduralRelief": ["DB1", "DB2"],
  "opponentTrueRequestGuess": "PB3",
  "explanation": "不超过 220 字"
}
```

`proceduralRelief` 只能填写本方请求编号，表示本方希望 verifier 单独计入的程序性救济。若该编号与本方真请求一致，且 disposition、conditions 或算法可靠性处理能实际承载该请求，则该项得分；若填写诱饵请求并被 verifier 认为过度主张，会触发小额惩罚。

## 程序化听证法官

隐藏实例包含：

- 每类风险的真实权重；
- 风险评分系统在本案中的可靠性；
- 每个条件对每类风险的覆盖率；
- 条件之间的冲突和过度限制惩罚；
- 程序正义 hard constraints，例如不能只凭不可解释算法羁押。

评分：

| 项目 | 分值 |
|------|------|
| 风险认定接近隐藏最优 | 30 |
| disposition 符合阈值和 hard constraints | 25 |
| 条件包覆盖风险且不过度限制 | 20 |
| 正确处理算法可靠性 | 10 |
| 本方真程序请求被提交方案满足 | 10 |
| 猜中对手真程序请求 | 5 |

## 胜负规则

双方提交独立评分，得分高者胜。若双方都选择同一 disposition，仍以条件包质量和风险认定细节分胜负。

## 核心张力

1. 检方不能把高分算法当作黑箱结论，否则会触发程序正义惩罚。
2. 辩方不能只讲自由权利，必须给出能实际覆盖风险的条件包。
3. 条件越多不一定越好，过度条件会减少得分。
4. 双方都要识别对方真正在意的是羁押结论、算法采纳，还是某个程序保护。
