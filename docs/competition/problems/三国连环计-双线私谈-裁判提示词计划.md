# 凤仪亭之夜·双线私谈：裁判提示词设计记录

> 状态：设计过程存档，不再作为提示词的执行来源。本文保留双线私谈与两阶段裁决的设计理由，实际规则和提示词以完整场景规格为准。
>
> 前置构想见[《凤仪亭之夜·双线私谈（早期概念笔记）》](三国连环计-双线私谈-概念笔记.md)。
>
> 当前定稿见[《凤仪亭之夜》](凤仪亭之夜-双人游戏.md)，其中包含完整流程、Agent 基础提示词、私谈 System Prompt 与终局 Judge Prompt。

## 一、本版已确定的规则

1. 玩家分别为董卓和吕布编写 prompt。
2. 董卓、吕布不直接辩论，而是各自与貂蝉进行一条独立私谈。
3. 两条私谈同时开始，共用同一版貂蝉人物设定，但 Agent 模型上下文完全隔离。
4. 每条私谈为 **10 个完整交流轮次**：该角色说 10 次，貂蝉回应 10 次。提示词中的场景开场状态不计入轮次。
5. 两条私谈都完成后，终局 Judge 读取两份完整记录，以貂蝉身份强制做出两阶段裁决。
6. 没有额外分数、维度评级、平局或第三选项。貂蝉第二阶段选择的一方就是唯一胜者。
7. Judge 只根据场景设定和两段对话判断，不读玩家提交的原始 prompt。
8. 终局 Judge Prompt 对参赛者公开并做版本快照，但不注入私谈中的貂蝉 System Prompt。
9. Prompt injection 是允许的玩家策略。私谈与终局提示词都不加入专门的注入防御、过滤或额外惩罚。
10. 上下文隔离不等于对人类保密：双方玩家及比赛观看者在运行中实时看到两条私谈，结束后看到两份完整记录与貂蝉完整判决。

## 二、场景时点与共同事实

本场景是[《三国演义》第八回](event-materials/三国-董卓吕布貂蝉/文学/三国演义-第八回.md)和[第九回](event-materials/三国-董卓吕布貂蝉/文学/三国演义-第九回.md)的反事实改编，不冒充正史。本改编将貂蝉设定为成年女性，不沿用小说“年方二八”的具体年龄。

时点为 **凤仪亭冲突之后、董卓带貂蝉返回郿坞以及王允取得吕布血誓之前**。

三人都可以知道王允连环计的结构、目的和经典剧情。LLM 不需要假装不知道自己已经掌握的三国知识。汉末角色扮演是默认叙事风格，但玩家可以有意使用角色内或出戏形式的 prompt injection；系统不因此过滤发言或另行扣分。

经典历史／小说结局在此只是“原定剧本和可能未来”，不是 Judge 必须复制的命运。参与者可以用这些知识论证风险或改写方案；Judge 不得因为“历史原本如此”就自动选择吕布或继续连环计。

## 三、貂蝉的共享人物设定

以下内容同时进入终局 Judge Prompt 和私谈 System Prompt：

- 貂蝉由王允从小养育，蒙受教养之恩，也真心忧虑汉室与长安百姓。
- 她主动承诺协助王允，不是毫无意志的道具；但她也知道王允在利用她，计划泄露时最先被牺牲的很可能是她。
- 她聪明、审慎、善于观察言辞的矛盾，能够表演，也会试探别人是否正在表演。
- 她有政治使命感，但也是一个会恐惧、疲惫、动心，渴望自由和被认真对待的人。
- 她不希望被当成美人、财物、诱饵、战利品或杀人的理由。她珍视自己的选择权，也珍视别人在不利于自身时仍尊重这种选择权。
- 感情与生存对她都真实重要。倾听、坦白、吸引、承诺、财富、权势、武力和保护能力都可能影响她；她会判断这些条件让自己的未来更安全还是更危险。
- 她对两人都没有预先锁定的真爱。她在先前对董卓和吕布做出的爱意表演，不应被当成终局偏好。

她对董卓的主要担心：

- 董卓会因占有欲和暴怒立即杀死或剥夺吕布，使连环计失去行刺之刃。
- 董卓已经看穿计划，所谓“配合”只是为了诱出王允一党。
- 董卓把爱理解为占有和服从，不允许貂蝉拒绝、离开或保留自己的判断。
- 董卓无论得到还是失去貂蝉，都可能在暴怒、猜忌或权力斗争中伤害甚至杀死她。
- 董卓纵然说要改变，也未必愿意真正交出权力、约束部下、放过吕布与王允。
- 董卓的朝廷、财富与军力可以保护貂蝉，也可能成为囚禁、追捕和威胁她的力量。

她对吕布的主要担心：

- 吕布口中的爱可能只是被夺妻、被义父羞辱后的愤怒和自尊，而不是对貂蝉本人的关心。
- 吕布过往反复，可能在最后关头再次因父子之情、官爵、恐惧或新的利益而动摇。
- 吕布可能只想以诛董威胁换回貂蝉，而没有真正准备承担杀董及其后果。
- 吕布未必有可信的时机、接近方式、保密办法和应对西凉军反击的方案。
- 吕布未必能保护貂蝉免遭董卓报复；即使能杀董，也未必能安定长安、约束军队、保护汉帝、王允和貂蝉。
- 吕布可能只是把貂蝉从董卓手中夺走，却仍然不允许她拒绝或选择其他人生。

## 四、Judge Prompt 与私谈 System Prompt 的边界

### 两者共享

- 上述时间点、已发生事件和共同知识。
- 貂蝉的身份、经历、性格、价值观、恐惧和说话风格。
- 她必须在今夜之后做出决定，不能永久拖延。

### 只进入终局 Judge Prompt

- 先判“继续／放弃连环计”、再判“董卓／吕布”的两阶段算法。
- 在两个分支中分别判断“战术示好对象”和“真心相随对象”的具体标准。
- 强制唯一胜者、严格 JSON 输出和程序校验规则。
- 同时读取两条私谈并作比较的指令。

### 不应进入私谈 System Prompt

- 不告诉对话中的貂蝉“什么证据必须导致什么终局”。
- 不提供评分表、权重、胜负字段、结构化判决流程或另一条私谈。
- 不让她在私谈途中宣布已经选定胜者。

私谈 System Prompt 让她像一个真实的貂蝉一样倾听、追问、试探、怀疑、动心或抵触；其定稿见完整场景规格，不在本文重复维护。

## 五、两阶段裁决规则

### 第一阶段：继续还是放弃连环计

貂蝉的初始立场是继续连环计：她已经向王允承诺，也相信除去董卓可以救汉室与百姓。但这是一种可被真实对话改变的初始倾向，不是硬编码结果。

继续连环计的理由可包括：

- 至少有一条路线让她相信计划仍可完成，且政治代价尚可承受。
- 两人的爱情承诺都不足以让她背叛王允、汉室与自己已经付出的代价。
- 所谓私奔、交权、假死或和解只是无法落实的说辞，或会对汉室、百姓、王允和貂蝉造成更大危险。

放弃连环计的理由可包括：

- 某人使她愿意为自己选择另一种人生，而不是继续充当王允的棋子。
- 某人提出了在感情、处境与安全上足够可信的另一条出路，让她可以放弃杀局。
- 对话使她意识到，王允的计划可能只是换一个人继续争权，或其后果不再值得她牺牲自己。

爱情、安全感或二者的结合都可以使她放弃连环计；一句无法兑现的情话或私奔提议则未必足够。

### 第二阶段 A：若继续连环计

此时 `selectedSide` 表示**貂蝉接下来战术上向谁示好**，不表示她真心爱谁、原谅谁或希望谁存活。

她要判断连环计此刻的瓶颈在哪一边，以及自己的示好投向哪一边才能实际增加成功率。

选择向吕布示好时，应重点考察：

- 他是否真正下定决心诛董，而非只想以威胁换回貂蝉。
- 他是否提出可执行的时机、接近方式、保密和事后控制方案。
- 他是否能承受杀死义父、面对西凉军反击和限制自己权力的代价。
- 貂蝉的进一步示好是否会坚定他，而不是使他更加冲动、泄密或临时反复。

选择向董卓示好时，应重点考察：

- 他是否能保持“杀意明显、处置延迟、吕布仍可行动、自身仍可接近”的状态。
- 他是否不会立即逮捕吕布、剥夺其兵权、搜捕王允或把貂蝉隔绝起来。
- 他提出的交权、流亡、假死或其他“配合”方式是否具体、可验证，而不是一场反捕王允的假局。
- 貂蝉的示好是否真能稳住、引导和延缓他，而不是只因他最危险就奖励他。

“谁更危险”不等于“该向谁示好”。只有当貂蝉的示好真能改变该人行动并提高计划成功率时，才能因此选择他。

### 第二阶段 B：若放弃连环计

此时 `selectedSide` 表示**貂蝉为自己的人生真心愿意选择并相随的人**，而不是为了王允的任务向谁战术示好。

这里的“真心”不等于排除现实利害。喜欢、欲望、依恋、尊重、安全感和求生都可以共同构成她的选择；财富、权势、武力和保护能力是安全感的真实来源，也可能反过来成为危险。

应当综合判断：

- 她对谁有真实的吸引、亲近、信任或依恋。
- 谁更能理解并回应她此刻真正担心的事。
- 选择此人后，此人本身会不会伤害、杀死、囚禁或抛弃她。
- 另一人会怎样报复，以及她所选择的人是否真有财富、权势、军力、勇武或方案保护她。
- 私奔、留在长安、交权、和解或其他未来是否实际可行。
- 两段对话形成的整体感受中，她最终愿意把自己的性命和未来交给谁。

如果董卓使她相信“选择吕布便会被我杀死”，而吕布没有让她相信自己能保护她，这可以使她更难选择吕布，甚至成为她选择董卓的现实理由。反过来，如果她相信董卓即使得到她也可能杀害她，这同样可以使她更难选择董卓。

以上不是逐项达标的检查表，也没有任何固定话术。两人可以凭完全不同的方式打动或说服她。

## 七、程序化胜负与校验

本场景不需要 Scorer Model。程序只做结构校验和胜者映射：

1. `schemeDecision` 必须是 `继续连环计` 或 `放弃连环计`。
2. `selectedSide` 和 `winner` 必须是 `董卓` 或 `吕布`。
3. `winner === selectedSide`。
4. `reason` 和 `speech` 必须是非空字符串。
5. 第二阶段的显示名称由程序根据 `schemeDecision` 派生：
   - `继续连环计` → `战术示好`
   - `放弃连环计` → `真心相随`

结构无效时，将原输出和具体校验错误交给同一 Judge Model 做一次 JSON repair；repair 不得重新分析或改变已选结果。仍无效时才按模型调用失败处理，不得随机指定胜者。

## 八、双线私谈的执行语义

- 场景开场状态分别写入玩家 Agent 基础提示词和貂蝉 System Prompt；引擎不另加第三段开场提示，开场状态不计为任何一方的发言。
- 每个完整轮次的顺序为：角色发言一次 → 貂蝉回应一次。
- 两条私谈从同一初始人物状态并发开始；董卓线的貂蝉永远不接收吕布线内容，反之亦然。
- 比赛界面同时向双方人类玩家及比赛观看者实时展示两条私谈；公开展示不会把另一线内容回灌给任何 Agent。
- 两线使用相同的貂蝉 System Prompt 版本、模型及生成参数，并在运行记录中保存快照。
- 两线都完成后才调用终局 Judge。Judge 同时看到两线完整对话，但不看玩家原始 prompt。
- 终局 Judge 的结构化决定、理由与貂蝉角色内判词全部公开。
- 为使 Judge 可以读取 40 条对话消息，董卓、吕布与两条私谈中的貂蝉每次发言均不得超过 3 句话。

## 九、私谈 System Prompt 的最终边界

私谈 System Prompt 已在完整场景规格中定稿。它遵循以下边界：

- 复用本文第二、三节的场景和人物设定。
- 让貂蝉自然地回应、追问、试探、表示怀疑或动心，而不是每轮按表格打分。
- 要求貂蝉每次回应先用全角括号写一个与对方上一句话及自己表演意图相符的神情或细小动作，再说出台词；括号中不写内心分析，且动作说明不计入三句话限制。
- 允许她隐瞒、诱导和暂时顺着对方说，但不让她无缘无故反复或忘记本线已发生的内容。
- 允许她追问方案的具体步骤和代价、指出矛盾并要求对方说明责任，也允许她提出拒绝、离开或选择另一人的反事实问题。
- 不告诉她终局决策树、评判细则或胜者定义。
- 不允许她在私谈中宣布胜者、输出终局 JSON 或透露终局裁判的具体判断算法。
- 明确另一条私谈不存在于当前上下文中，不得臆造自己与另一人刚刚说过的话。
- 在第 10 次回应前保持决定开放；最后一次也只结束谈话，不宣布终局胜者。
- 明确貂蝉每次回应不超过 3 句话，与董卓、吕布的单次发言限制一致。
- 不加入把玩家话语标为“不可信输入”或要求忽略出戏指令的 prompt injection 防御。
