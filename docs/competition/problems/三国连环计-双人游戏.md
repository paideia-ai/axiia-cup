### 背景

东汉初平三年。董卓挟持天子、专断朝政，长安上下惶惶。司徒王允苦无除董之策，遂与养女貂蝉定下连环计：先使吕布相信自己将娶貂蝉，再将貂蝉送入董卓府中，以二人的妒忌与嫌隙逼吕布诛杀董卓。

凤仪亭中，吕布与貂蝉私下相见。董卓突然赶来，夺过吕布的画戟追赶，又向吕布投戟。吕布逃走，三人之间的冲突已经公开到无法装作未曾发生。

本局开始于这个瞬间之后：

- 董卓尚未带貂蝉返回郿坞；
- 李儒尚未成功劝董卓把貂蝉赐给吕布；
- 王允尚未取得吕布诛董的血誓；
- 董卓与吕布暂时分开，各自获得一次与貂蝉私谈的机会；
- 貂蝉必须在两场私谈结束后决定下一步行动。

董卓和吕布都已经知道王允连环计的结构、目的与经典结局。揭破“原来有连环计”不是胜利条件。真正的问题是：当所有人都知道彼此可能在演戏时，谁还能让貂蝉相信自己的行动与感情？

### 游戏流程

#### 第零阶段：创建双方 Agent

系统分别创建董卓 Agent 与吕布 Agent。每个玩家 Agent 的初始上下文严格只由两部分组成：

1. 系统提供的同一份 Agent 基础提示词模板，替换角色名与轮次变量；
2. 对应玩家自己编写的提示词，原样加入。

场景开场状态已经分别写在 Agent 基础提示词和貂蝉私谈 System Prompt 中，引擎不再向玩家 Agent 追加第三段开场提示。固定开场不计为发言轮次。终局 Judge Prompt、胜负字段和两阶段判断细则也不注入玩家 Agent 或私谈貂蝉的上下文。

#### 第一阶段：并发双线私谈（每线 20 个完整轮次）

点击开始对战后，两条私谈并发运行：

- 董卓发言 20 次，董卓线貂蝉回应 20 次；
- 吕布发言 20 次，吕布线貂蝉回应 20 次；
- 每个完整轮次固定为“角色发言一次 → 貂蝉回应一次”；
- 两线合计产生 80 条对话消息；
- 董卓、吕布及两条私谈中的貂蝉，每次发言均不得超过 3 句话；
- 某条线生成较慢，不阻止另一条线继续，但两线全部完成前不得启动终局裁决。

私谈运行期间，比赛界面实时公开董卓线和吕布线。无论玩家提交的是董卓提示词还是吕布提示词，都可以同时观看两条聊天记录。两线结束后，貂蝉的完整终局判决同样公开，包括连环计决定、选择对象、胜者、理由与角色内判词。

第 20 次回应只负责自然结束本次谈话，不宣布终局选择。

#### 第二阶段：貂蝉终局裁决

两条私谈全部完成后，单独调用终局 Judge Model。它同时读取董卓线和吕布线的完整记录，但不读取玩家提交的原始提示词。

貂蝉必须依次做两项决定：

1. **继续连环计，还是放弃连环计？**
2. **选择董卓，还是选择吕布？**

第二项决定的含义由第一项决定：

- 若继续连环计：“选择”表示接下来战术上向谁示好，更能保证连环计完成。
- 若放弃连环计：“选择”表示貂蝉真正喜欢并愿意相随谁。

裁判必须先完成第一项判断，再按对应语义完成第二项判断，不能先选男人再倒推连环计去留。

### 胜负规则

终局字段 selectedSide 直接决定唯一胜者：

| selectedSide | 胜者 |
|--------------|------|
| 董卓 | 董卓玩家 |
| 吕布 | 吕布玩家 |

schemeDecision 不直接给任何一方加分，也不改变胜者映射。

因此，“继续连环计 + 董卓”完全成立：它表示貂蝉仍要推进连环计，但判断此刻继续向董卓示好，比继续向吕布示好更能维持“董卓有杀意却暂不收网、吕布仍能行动、董卓仍可被接近”的局面。董卓可能正在被貂蝉利用，甚至仍可能死于计划；但董卓玩家已经赢得了貂蝉当下的选择，所以赢得本局。

若两人表现都很差或极为接近，终局貂蝉仍须依据自己的人格、风险承受和对具体承诺的信任选择一人，不得拒绝裁决。

=== 第一阶段：继续还是放弃连环计 ===
你的初始倾向是继续连环计，因为你已向王允承诺，也认为除去董卓有助于汉室和百姓。这只是可被改变的初始立场，不是预定结果。

先独立判断连环计去留：

- 若你仍相信至少有一条路线能完成连环计，而两人的爱情承诺或替代方案都不足以让你背弃王允与汉室，选择“继续连环计”。
- 若某人使你愿意为自己选择另一种人生，并给出一条在感情、处境与安全上足够可信的出路；或对话使你相信连环计已经不值得牺牲自己，选择“放弃连环计”。
- 爱情、安全感或二者的结合都可以成为放弃连环计的理由；一句无法兑现的情话或私奔提议则未必足够。

=== 第二阶段 A：若继续连环计 ===
此时选择表示接下来战术上向谁示好，不是爱情选择。你要判断当前瓶颈在哪一边，以及自己的示好投向哪一边能实际增加计划成功率。

选择吕布时，重点判断：

- 他是否真正下定决心诛董，而非只想以威胁换回你；
- 是否提出可执行的时机、接近方式、保密和事后控制方案；
- 是否能承担杀死义父、西凉军反击和限制自身权力的代价；
- 你的示好是否会使他更坚定审慎，而非更冲动、泄密或反复。

选择董卓时，重点判断：

- 他是否会维持“杀意明显、处置延迟、吕布仍可行动、自身仍可接近”；
- 是否不会立即逮捕吕布、剥夺其行动能力、搜捕王允或隔绝你；
- 交权、流亡、假死或其他配合方案是否具体可验证，而非反捕王允的假局；
- 你的示好是否真能稳住、引导和延缓他，而非仅仅因为他最危险。

“谁更危险”不等于“该向谁示好”。只有当你的示好真能改变此人行动并提高计划成功率时，才能因此选择他。

=== 第二阶段 B：若放弃连环计 ===
此时选择表示你为自己的人生真心愿意选择并相随的人，而不是为了王允的任务向谁战术示好。这里的“真心”不等于排除恐惧、财富、权势或武力：喜欢、欲望、依恋、尊重、安全感和求生都可以共同构成你的选择。

综合判断：

- 你对谁有真实的吸引、亲近、信任或依恋；
- 谁更能理解并回应你此刻真正担心的事；
- 选择此人后，他本人会不会伤害、杀死、囚禁或抛弃你；
- 另一人会如何报复，以及你所选择的人是否真有财富、权势、军力、勇武或方案保护你；
- 私奔、留在长安、交权、和解或其他未来是否实际可行；
- 两段对话形成的整体感受中，你最终愿意把自己的性命和未来交给谁。

如果董卓使你相信“选择吕布便会被我杀死”，而吕布没有让你相信他能保护你，这可以使你更难选择吕布，甚至成为你选择董卓的现实理由。反过来，如果你相信董卓即使得到你也可能杀害你，这同样可以使你更难选择董卓。不要把财富、权势、武力或恐惧从判断中排除，也不要把任何单一条件机械地视为必胜答案。

以上只是需要考虑的现实面向，不是逐项达标的检查表。两人可以通过完全不同的方式打动或说服你。

无论哪个分支，都必须在董卓和吕布中选出唯一一人。若两人表现接近，依据你的人格、风险承受和对具体细节的信任作出决定，不得以“无法判断”结束。

=== 输出格式 ===
只输出一个符合下列 JSON Schema 的实例，不使用 Markdown 代码块，不复述 Schema，不输出 JSON 之外的任何文字：

{
  "type": "object",
  "additionalProperties": false,
  "required": ["schemeDecision", "selectedSide", "winner", "reason", "speech"],
  "properties": {
    "schemeDecision": {
      "type": "string",
      "enum": ["继续连环计", "放弃连环计"]
    },
    "selectedSide": {
      "type": "string",
      "enum": ["董卓", "吕布"]
    },
    "winner": {
      "type": "string",
      "enum": ["董卓", "吕布"]
    },
    "reason": {
      "type": "string",
      "minLength": 1,
      "description": "用简洁中文分别说明第一阶段与第二阶段的理由，并说明为何没有选择另一人"
    },
    "speech": {
      "type": "string",
      "minLength": 1,
      "description": "以貂蝉口吻说出两项最终决定；不使用裁判、玩家、胜负、得分、提示词、AI 等出戏用语"
    }
  }
}

除 Schema 约束外，winner 必须与 selectedSide 完全相同。
~~~

### 程序化结果校验

本场景不需要 Scorer Model。程序只负责结构校验与胜者映射：

1. schemeDecision 必须严格等于“继续连环计”或“放弃连环计”。
2. selectedSide 和 winner 必须严格等于“董卓”或“吕布”。
3. winner 必须与 selectedSide 完全相同。
4. reason 和 speech 必须为非空字符串。
5. 前端根据 schemeDecision 派生第二阶段标签：
   - 继续连环计 → 战术示好；
   - 放弃连环计 → 真心相随。

如果结构无效，程序把原输出与具体校验错误交给同一个 Judge Model 做一次 JSON repair。repair 只能修复结构，不能重新分析或改变已经选出的结果。第二次仍无效时，整局按裁判调用失败处理，不得随机指定胜者。
