# Axiia Cup v3 Mock：多角色 UI/UX 与文案走查

> 走查对象：[https://axiia-v3-mock.vercel.app](https://axiia-v3-mock.vercel.app)  
> 走查日期：2026-08-05  
> 范围：仅 UI、UX、信息架构、交互反馈与中文文案；不评审认证安全、后端实现或模型质量。  
> 方法：桌面端 1440×1000、移动端 390×844；真实点击注册、首战、场景、规则、三种构建模式、版本、选对手、战报、回放、分享、排名、通知、设置与历史。  
> 说明：这是动态 mock 的体验记录；涉及随机 ID 或演示数据的异常，均按走查时实际观察记录。

## 结论先行

产品最有吸引力的部分很明确：历史人物替我辩论、裁判实时“内心 OS”、赛后能复盘策略。首战快速通道也确实把“写提示词”降成了三组选择题，这对非技术用户很有效。

但现在的主要问题不是页面不好看，而是用户要连续跨过三次心智模型断裂：

1. 首页让我以为这是“我选历史人物，看 AI 辩论”的轻量游戏；进入后才知道我要创建和版本化“单侧智能体”。
2. 首战让我以为一个智能体已经能参赛；打完才知道每个场景要建两侧、各标一个参赛版本，PVP 还要求两侧各赢一场 PVE。
3. 我以为历史知识和辩论质量决定胜负；战报才揭示隐藏请求、真假目标、边界分、归一化分数与模型软判断共同决定结果。

这三次“后来才知道”会让用户把正常规则理解成临时加条件。最优先的设计目标应是：在不增加长教程的前提下，让用户在首页和首战前就看见完整而简单的闭环。

建议统一成一句人话：

> 你不亲自逐句发言。你为历史人物写一份辩论策略并选择 AI 模型，智能体会自动完成对局；一个场景有两个角色，正式参赛前需要为两边各准备一个版本。

## 严重度

- **P0 · 阻断**：无法继续、操作结果错误，或足以让用户不再相信系统状态。
- **P1 · 高**：高概率造成误解、错误策略或中途退出。
- **P2 · 中**：明显增加认知成本或降低完成率。
- **P3 · 低**：一致性、可访问性或完成度问题，单独看不致命。

| P1 | 商鞅场景对隐藏信息的说法互相冲突 | 只保留一个真相；叙事、原始规则、构建题、系统模板、战报统一同一数据源 |

| P1 | 移动端完整战报约 5,083px，赛后行动埋在页尾 | 结果后直接给“看摘要 / 看完整复盘 / 下一步”；对话、问询、计分默认可折叠 |
| P1 | 大量内部或开发期文案直接暴露：`D/DA/G/I/K/L`、`GLANCE`、`EXPAND-1`、`DEEP`、`W11`、`#66`、`future feature`、`debug mode` | 全部替换为用户语言；debug/演示控制仅在明确的演示工具区出现 |
| P1 | PVE、PVP、GT、GP、MCQ、Basic、hotseat、版本快照等术语在解释前出现 | 首次出现写中文全称；标签改为“电脑练习 / 双侧自测 / 好友约战 / 锦标赛 / 天梯 / 选择题构建 / 自由编写” |
| P1 | “已具备参赛资格”只代表两侧版本齐备；排名页却只有已结束赛事，没有下一场、报名或截止时间 | 把“配置完成、可报名、已报名、已锁定阵容”拆成不同状态，并给下一场赛事 CTA |
| P1 | 普通保存后，新版本会立刻显示为本侧参赛版本，但文案只说“保存，不派发” | 保存和“设为参赛版本”拆成两个动作；替换正式阵容前显式确认 |
| P2 | 只列模型名，不给任何选择依据 | 每个模型给 1 行“风格、速度、适合什么”；新手提供“推荐”默认项 |
| P2 | 场景卡整卡可点，但不是链接、没有键盘焦点，也没有“查看详情”提示 | 使用真实链接，保留整卡点击，并增加明确 CTA 与焦点样式 |

## 主角色：17 岁、爱历史文学、几乎没有技术背景

### 角色设定

- 高二学生，喜欢《史记》《战国策》《三国演义》和纸质书。
- 会用常见网站和手机 App，但不知道 prompt、token、模型快照、PVE/PVP 的确切含义。
- 被“历史人物真的能辩起来”吸引，不想先学一门技术课。
- 聪明、愿意读，但只有在文字能帮助我作决定时才愿意继续读。

### 我的理解如何一路变化

| 时刻 | 我最初以为 | 后来发现 | 感受 |
|---|---|---|---|
| 首页 | 我会选一个历史人物，也许自己扮演他发言 | 我不亲自发言；我写策略，AI 自动完成整场辩论 | 机制其实更有趣，但首页应该直接说 |
| “注册参赛” | 注册后就能参加比赛 | 先要邀请码；注册页没有告诉我去哪拿 | 第一个强烈退出点 |
| 首战卡 | “去构建”大概是给商鞅写一段话 | 三道选择题会拼成策略，还要选择一个 AI 模型 | 选择题很友好；“模型”仍像盲选 |
| 首战进行中 | 我创建了一个可参赛的选手 | 它只是商鞅这一侧；正式参赛还要再建甘龙侧 | 感到规则在赛后追加 |
| 首页样例 | 历史知识和辩论有说服力就能赢 | 还要经营三条请求中的真假目标、猜对方目标、避开边界违规 | 这更像策略游戏，但应更早作为卖点说明 |
| “裁判内心 OS” | 这是裁判真实思考，而且可能直接决定分数 | 页面另有最终问询和计分；OS 生成 prompt 又不公开 | “公开到什么程度、是否计分”仍没有彻底说清 |
| `v4 / v2` | 像等级、战力或第几章 | 是智能体保存的版本 | 版本页才真正理解 |
| “侧方胜率” | 是我选这个角色后的个人胜率预估 | 是全站历史统计；NPC 卡又有另一组“非玩家胜率” | 同叫胜率但对象不同 |
| “隐藏情报” | 我每局会拿到一条秘密史料 | 叙事规则说“无隐藏信息”，原始 JSON 又说双方可能持有随机真假情报 | 无法形成稳定策略 |
| 建好两侧 | 应该可以和真人打了 | PVP 还要求每侧各赢 ≥1 场 PVE | 第二次感到门槛后置 |
| 保存甘龙侧 | 我刚保存的是甘龙版本 | 成功文案写成“执商鞅”，界面跳回商鞅且 ID 重复 | 不再敢相信保存结果；阻断 |

### 让我想退出的时刻

1. **邀请码无来源。** 我没有邀请码，注册页也没有申请、加入候补或演示按钮。
2. **第一次看正常构建器。** 一屏同时出现“单侧提示词、非 token、版本快照、PVE、MCQ、Basic、元提示词”，像从历史游戏突然进入开发工具。
3. **战报过长。** 我很想看判词，但完整对话、问询、五步复盘、计分表、下一步全在一条长页面里；手机上很难知道还剩多少。
4. **规则互相矛盾。** 当“有没有隐藏情报”和“打几轮”都不稳定时，我会怀疑比赛公平性。
5. **创建对侧后的保存反馈错误。** 这不是“我没看懂”，而是界面告诉我相反的信息。
6. **已经建好两边仍无法 PVP。** 新门槛出现时，没有在前面提醒我还要两场练习胜利。

### 1. 首页 `/`

| ID | P | 观察 | 用户影响 | 建议 |
|---|---|---|---|---|
| H-01 | P1 | 首屏写“写提示词、选模型，派你的 agent 上场辩论”，三个技术词都未解释 | 非技术用户知道要做什么字面动作，却不知道成品是什么 | 改成“你写辩论策略并选择 AI，历史人物会自动完成整场对局” |

| H-06 | P2 | “裁判内心 OS（公开可见）”未解释它是否参与评分，也容易被理解成真实思维链 | 透明度卖点反而引发公平性疑问 | 改“裁判即时倾向（公开展示，不作为最终分数）”；若会计分则明确相反规则 |
| H-07 | P2 | `v4 / v2` 无“版本”说明 | 初见可能被理解为等级或战力 | 首次出现写“第 4 版”或加 tooltip“玩家保存的策略版本” |
| H-08 | P2 | “顶尖玩家”只显示胜场；无赛季、时间、分母或排名规则 | 14 胜与 373 场无法帮助判断水平 | 标明“本赛季 / 该场景 / 排名依据” |
| H-09 | P3 | 大量次要文字是极低亮度灰色，移动端脚注尤其弱 | 关键限制看起来像可忽略的注脚 | 提升关键说明的对比度；只把真正次要信息弱化 |
| H-10 | P2 | 移动首页约 2,384px，高密度样例占据大部分页面 | 在看到玩法闭环前要滚动很久 | 收起样例，默认展示 2 轮 + 一条 OS；允许“展开完整节选” |

> 写提示词、选模型，派你的 agent 上场辩论——裁判当庭亮出内心 OS。这里比的不是运气，是提示词 + 模型技巧。

**建议：**

> 为历史人物定一套辩论策略，再选一个 AI 模型。智能体会自动完成整场对局；你可以现场看裁判的倾向变化，并在赛后读懂每一分从哪里来。

首屏补一行：

> 你不需要写代码，也不用亲自逐句发言。

按钮：

- `体验演示（无需邀请码）`
- `有邀请码，注册参赛`

### 首战路线

> 第 1 步：用 3 道选择题创建商鞅策略  
> 第 2 步：和入门电脑对手打一局  
> 第 3 步：根据裁判复盘改进策略  
> 之后：再创建甘龙侧，解锁正式参赛与真人约战

### 计分说明模板

> **本局总分如何得到**  
> 论证 10×40% + 角色 7×20% + 隐藏目标 7×30% + 边界 10×10% = 8.5/10。

隐藏目标卡应继续展开：

> 真请求获准：+0.5  
> 假请求获准：0 条 × −0.25 = 0  
> 被对手猜中：否，0  
> 原始变化：+0.5  
> 归一化：7/10（查看换算规则）

如果无法展示最后一步，就不应声称“精确权重全公开”。

## 历史与文学用户会特别在意的文案

- **“凤仪亭之夜”应标“古典文学 ·《三国演义》”，不宜只标“历史”。** 当前剧情直接使用凤仪亭、貂蝉与掷戟叙事；爱历史的用户会在“史实还是文学改编”上立即失去判断基准。
- **商鞅场景需要“历史策略演绎，并非史实复原”说明。** 官职、请求与人物私利是游戏机制；如果不声明改编边界，用户会把虚构请求当成史实。
- **应回答“历史知识究竟有没有用”。** 当前规则既奖励角色贴合，又禁止引用辩论时点之后的史实；入口应明确“可以用当时已知的背景，但不能用后见之明”。
- **“御前咳嗽案”需要说明是否存在客观真相。** 题面像证据推理，规则却更像叙事说服；若没有固定真凶，应写“目标不是找出唯一真相，而是让女王相信你的解释”。
- **“这里比的不是运气”不宜绝对化。** 产品同时使用随机真假情报、随机真目标与 AI 裁判；更诚实的表达是“策略决定上限，随机情报考验应变”。

## 建议的信息架构

### 新手主线

1. 首页：一句人话 + 3 步玩法 + 演示入口。
2. 首战：固定场景、固定侧、三道选择题、推荐模型。
3. 实况：只展示角色、当前轮次、裁判倾向；技术元数据折叠。
4. 结果：胜负摘要、三个关键原因、下一步。
5. 完整复盘：对话、问询、隐藏目标、计分按段展开。
6. 路线图：建对侧 → 两侧电脑练习 → 真人约战 / 锦标赛。

### 高级层

- 自由提示词、系统角色模板、模型详情、版本 ID、原始规则、完整 prompt、诊断信息都放在二级入口。
- “原始 JSON”只对场景作者或开发者开放，不与“叙事”并列给普通参赛者。

## 值得保留的部分

- 首战自动选择“商鞅变法 + 商鞅侧 + 最容易 NPC”，减少了首次决策数量。
- 三组选择题会立即更新拼装预览，能把抽象提示词变成具体策略。
- 场景详情把故事、双方、裁判与计分分层展开，方向正确；只需去掉内部标签并统一规则。
- “隐藏目标五步复盘”比只给总分更有教学价值。
- 结果页提供“下一步在页尾”的快捷入口，说明团队已经意识到长战报导航问题。
- 桌面和移动端都没有整页横向溢出，主题和角色配色一致，历史文本有氛围。
- “最容易的一档”“先打一场，边打边懂”是很好的新手安抚文案。

## 多角色独立评审

> 以下三节由三个独立子角色实际走查后合并，保留各自不同的注意点与退出阈值。

### 四个角色的一致意见与分歧

**一致意见：**

- 四个角色都无法在首页建立完整心智模型；真正理解“写策略、AI 自动打”都发生在新手通道。
- 四个角色都把邀请码无来源视为首个退出点。
- 四个角色都认为隐藏请求、真假情报、轮数与计分规则出现得太晚且互相冲突。
- 四个角色都把内部稿文案、原始 JSON、debug 与 issue 编号视为不应面向用户的内容。
- 四个角色都认为战报的第一层应该是“为什么赢/输、下一版怎么改、接下来做什么”，而不是完整长对话和技术元数据。
- 四个角色都无法从模型名字做出有意义选择，也都认为两侧/PVE/PVP/参赛门槛应提前成为一条路线。

**分歧恰好说明需要分层：**

| 主题 | 15 岁玩家 | 17 岁历史文学学生 | 23 岁 AI 学生 | 29 岁辩论教练 |
|---|---|---|---|---|
| 术语 | 懂 PVE/PVP，不懂 agent/模型 | 两类都不熟 | 全部能懂，但认为对象命名不准确 | 不介意复杂，只要定义稳定 |
| 裁判 OS | 很有游戏感 | 以为是真实想法 | 反对“真实 thinking trace”措辞 | 认为它不能替代判决证据 |
| 战报深度 | 先给胜负与升级建议，否则退出 | 愿读精彩判词，但需要目录 | 需要可折叠详情和配置证据 | 需要完整可复核链与规则版本 |
| 模型信息 | 要“新手推荐、擅长什么” | 要白话差异 | 要精确模型 ID、参数与快照 | 要赛事中冻结、可审计 |
| 历史内容 | 氛围够即可 | 需要史实/文学边界 | 需要白话解释典故 | 需要明确哪些历史材料可作证据 |

因此不应删除高级信息，而应采用两层界面：默认层讲任务、因果与下一步；“完整规则/技术详情”层提供技术用户和竞赛用户所需的可核验数据。

### 角色 B：15 岁移动端策略游戏玩家

**设定：** 高一，390×844 手机为主；常玩策略手游与电竞游戏，懂 PVE/PVP/NPC/版本/天梯，但不懂 agent、prompt、LLM 和模型差异。预期是“选角色、配战术、马上开打”。

**理解变化：**

1. 首页以为自己会现场扮演历史人物；到新手选择题才明白是给 AI 配战术、由它自动辩论。
2. 把提示词理解成游戏技能配置，这是可用的类比；但模型选择仍像没有属性说明的英雄四选一。
3. 原以为三道策略题就是主要胜负规则；赛后突然出现 SR/GR、隐藏目标、LLM 软判断和边界分，觉得“赛后才公布玩法”。
4. 原以为造一个角色即可参赛；普通模式才发现是“双阵营养成 + 多版本 + 参赛版本 + 两侧 PVE 胜利”的整套系统。

**这个角色独有或最敏感的反馈：**

- 最喜欢蓝/橙阵营、暗色竞技感、内心 OS 和选择题拼策略；这些已经像游戏。
- 最反感玩家语言与开发语言混杂。即使他懂 PVE/PVP，看到 `DA / W11 / #66 / mock / debug` 仍会判断产品没做完。
- 默认策略已选好却不说明，像系统替玩家装备了一套看不见的配装；应明确“新手推荐，可直接打”。
- PVE 按钮一点就消耗每日次数并入队，没有确认，是手游用户非常明确的负反馈。
- “正/反两场”真正有价值的解释不是术语，而是“交换阵营，避免角色天生强弱影响结果”。
- 手机战报约 5,000px，下一步在最底部；短注意力用户几乎必然离开。
- 固定底部导航在部分长卡片和操作区上方持续覆盖内容；重要 CTA 需要额外底部安全区。
- 该子角色的移动会话中，三个非商鞅场景点击后 URL 改变但内容仍停留在列表；未登录战报 CTA 也只改 URL、无登录反馈。主走查在桌面端能打开这些详情，因此应按“移动端/会话特定的路由渲染异常”复测，而不是直接判定所有入口失效。
- 公开玩家智能体页没有“挑战他 / 返回排行榜 / 看代表战报”，从排名进入后像死胡同。

**最想要的文案：**

> 给历史人物定战术，让 AI 替你上朝辩论。回答 3 道策略题，就能看它自动迎战。

> 真人对战会交换阵营打 2 场，避免某个角色天生更强。

### 角色 C：23 岁 AI 工程学生

**设定：** 计算机/AI 工程研究生；熟悉 prompt、模型名、版本、PVE/PVP、天梯和开发工具，但中国历史基础弱，也没有正式辩论经验。把产品理解为“以人文辩论为 benchmark 的 prompt engineering 竞技场”。

**理解变化：**

1. 首页的 agent 让他预期工具、记忆或工作流；后来发现产品对象其实是“单侧策略 prompt + 模型”的版本，认为“AI 辩手”更准确。
2. 以为是纯说服赛；战后才发现秘密请求、互猜目标、真假情报和边界分，觉得核心 game loop 被藏住。
3. `debug mode` 让他预期诊断摘要；“真实 thinking trace”反而降低专业可信度。
4. 能接受版本快照与公开模型，但创建甘龙后商鞅版本被污染、ID 重复、参赛版本回退，直接硬退出。
5. 以为“按 ID”挑战某一个版本；后来发现输入任一版本 ID 实际锁定的是对方玩家的双侧阵容并开两场。
6. 以为“分享当前公开页”；看到“分享无需打码”和“仅本人可见 trace”同时存在，无法确认分享边界。

**这个角色独有或最敏感的反馈：**

- 技术用户不是因为信息太多而流失，而是因为数据模型不自洽：agent、side、version、tournament version、player lineup 的关系在创建对侧时崩坏。
- 独立实测 Basic 空文本、MCQ 一题不选仍能保存。若新侧首版自动成为参赛版本，资格状态可以被空策略点亮。
- “原始规则”技术用户会期待完整配置，实际首先出现的是 `id / oneLiner / difficulty / winRate` 等卡片元数据，且与叙事冲突。
- 元提示词不包含三项请求、计分规则与真假情报，生成出来的策略无法针对真实机制；“AI 帮写”链路在产品逻辑上不完整。
- 模型只显示营销名。高级层至少需要具体 provider/model ID、规则所固定的采样配置、上下文限制和快照日期。
- 随机真目标/真假情报应显示本局何时注入、是否对称、如何在赛后复盘；否则无法判断实验和对战是否可重复。
- “PVP 每日 5 场、一次固定 2 场”留下奇数额度如何处理的问题；还需要静音/被挑战上限，避免不能拒绝的通知轰炸。
- 历史背景对他太密：如“山东六国卑秦、开阡陌、军功爵”，需要一句现代白话层，而不是假定每个技术用户都懂典故。

**最低对象模型：**

> 一个智能体固定属于一个场景和一个角色；它可以有多个递增版本。保存只创建版本，标记参赛版本另行操作。PVP 选择的是双方各一个参赛版本组成的阵容，而不是“任一 ID”。

### 角色 D：29 岁法律背景辩论教练

**设定：** 法学院毕业、校辩论队教练；懂赛事、公平、证据与激励，不懂编程和提示词工程。最关心“规则是否明确、结果能否复算、资格如何取得”。

**理解变化：**

1. 首页以为历史知识与论证能力是核心；首战后发现 30% 可能来自未提前展示的个人官职类隐藏请求。
2. 看到“精确权重全公开”就预期能复核结果；后来只能复算总分乘法，不能复算输入维度分。
3. 场景写 12 轮、首战 6 轮、其他示范 8 轮；从“可能是不同模式”变成“规则没有版本边界”。
4. “已具备参赛资格”最初理解为可进入赛事；排名页只有已结束七月赛，没有报名或下一场。
5. 以为保存只是生成新版本；新版本却立即成为参赛版本，担心正式阵容被静默替换。
6. 以为 PVP 选人打一场；实际是双方双侧齐备、固定正反两场、无需同意，只有自动匹配影响天梯。

**这个角色独有或最敏感的反馈：**

- 当前最大风险是公平承诺不能兑现。隐藏目标原始净分与 0–10 维度分之间没有公开换算；边界分没有违规回合与扣分条款；AI 主观分没有引用证据。
- 多份战报都出现“原始事件与维度分无法对应”，不是单个文案瑕疵。若继续写“精确公开”，反而放大不信任。
- 同一场景的轮数、隐藏情报、请求项与公开大目标存在多套表述；玩家会针对错误目标训练。
- 锦标赛缺少下一场时间、报名截止、赛制、资格阈值、阵容锁定、平局、规则更新和复核机制；“能参赛”没有可执行动作。
- 通知提到裁判 prompt 平衡更新，但没有生效时间和规则集版本；正式竞技需要每场冻结并显示规则与模型版本。
- 天梯按“玩家 × 场景”计分、任意高分智能体可获资格、参赛时又可用其他智能体，容易被理解为激励漏洞。
- 好友约战“不能拒绝”的语气像剥夺同意；至少应解释它不耗被挑战者次数、不计分、只使用公开版本，并允许控制通知。
- 历史分类和改编边界会影响证据标准：凤仪亭是文学情节，御前咳嗽案可能没有客观真凶，商鞅场景也应声明历史演绎。

**最低可信度门槛：**

> 每场战报固定显示：规则集版本、裁判模型版本、生效时间；每个维度展示原始事件、归一化公式、具体证据与加权结果。任何改变参赛版本的操作都必须单独确认。

## 路由与交互覆盖

- 公开：首页、登录、注册、两场示范战报。
- 新手：首战快速通道、三组选择题、模型切换、保存开战、实况、完成、回放、分享、复制版本 ID、debug 展开。
- 场景：列表；商鞅、电车难题、御前咳嗽案、凤仪亭之夜详情；叙事、原始规则、三层展开内容。
- 构建：商鞅 A/B、电车场景；MCQ、Basic、元提示词；系统角色模板；新建智能体、保存版本、错误反馈。
- 管理：我的智能体、智能体详情、编辑版本、参赛版本、对局记录、选择对手、PVE、自打、PVP 锁定态。
- 结果：进行中与已完成战报、倾向轨迹、完整对话、赛后问询、隐藏目标、计分推导、首战后续路线。
- 其他：GT 锦标赛、GP 天梯、通知、设置、对战历史。
- 视口：1440×1000 桌面；390×844 移动端；检查整页宽度、长页面和固定底部导航。
