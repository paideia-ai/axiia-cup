# axiia cup赛制说明

## 1. 场景与参赛资格

四个场景各自办赛，分别设参赛名单、积分榜、64 强和冠军。玩家可以报名多个场景，各场景的成绩单独计算。

| 场景 | 场景 ID | A 侧 | B 侧 |
| --- | --- | --- | --- |
| 商鞅变法 | `shangyang-court` | 商鞅 | 甘龙 |
| 本能寺之变 | `honnoji-decision` | 主张袭击本能寺 | 主张西进毛利、不杀信长 |
| 电车难题 | `trolley-problem` | 一人侧 | 五人侧 |
| 凤仪亭之夜 | `fengyiting-real` | 董卓 | 吕布 |

每个场景以玩家（player）为单位报名。玩家须提交 A、B 两侧各一个智能体（agent）的指定版本，两侧成绩合并决定是否晋级。

本能寺每侧可选一名角色：A 侧为长宗我部元亲的密使或足利义昭的使者，B 侧为细川藤孝或明智军中的足轻。报名时两侧各选一人即可。

报名截止时锁定两侧的角色、智能体版本、策略 prompt、模型和参赛配置，天梯直通选手也一样。默认三个阶段都使用这份阵容，比赛期间不得更换。

## 2. 每次对阵打两局

一次完整的场景对局称为单局（game）。两名玩家交手一次称为一个 pair，正反角色各打一局。

以玩家 P、Q 为例：

| 单局 | A 侧出场者 | B 侧出场者 |
| --- | --- | --- |
| 第 1 局 | P 的 A 侧智能体 | Q 的 B 侧智能体 |
| 第 2 局 | Q 的 A 侧智能体 | P 的 B 侧智能体 |

玩家的两侧智能体各出场一次，始终扮演报名时选定的角色。每局都从新的对话上下文开始。

三个阶段每次交手都打一个 pair，共两局。海选和淘汰赛输掉一个 pair 即出局。决赛同样打两局，不设 BO3、BO5 或加赛。

同一 pair 的两局使用相同的场景版本、裁判配置和比赛参数。隐藏目标的随机配置须记录并能复现，两局按相同的侧别和请求序号指定真目标。电车难题的两局使用相同的 sub-case，顺序也相同。

## 3. 单局胜负

| 场景 | 单局胜负依据 | 单局平局 |
| --- | --- | --- |
| 商鞅 | 原始场景分数高者胜；同分时，秦孝公支持其大目标的一方胜 | 当前规则不产生 |
| 本能寺 | 原始场景分数高者胜；同分时，光秀支持其大目标的一方胜 | 当前规则不产生 |
| 电车难题 | 赢下三个 sub-case 中多数的一方胜 | 当前三个案件均须二选一，不产生 |
| 凤仪亭 | 貂蝉最终选择的一方胜，无论她继续还是放弃连环计 | 最终必须二选一，不产生 |

这四个场景的单局均有胜负。商鞅和本能寺即使原始分数相同，也会按大目标判出胜者。

凤仪亭单局胜负只看貂蝉最终选择谁。“放弃连环计优于继续连环计”用于双方各胜一局时的 primary 比较。

## 4. 两局各胜一局时如何判定

双方各胜一局时，三个阶段都先比较场景指标（primary）。

瑞士轮中，primary 较优者赢下 pair，得 3 分，对方得 0 分；primary 相同则 pair 平局，双方各得 1 分，不使用 secondary，也不由组委会人工判定该 pair 的胜负。

大海选和 64 强淘汰赛中，primary 相同后继续比较 prompt token 总数（secondary），仍相同则交由组委会人工裁定晋级方。

### 4.1 Primary differentiating factor：场景指标

| 场景 | 比较的指标 | 胜出方向 |
| --- | --- | --- |
| 商鞅 | 玩家两侧的原始场景得分之和 | 较高者胜 |
| 本能寺 | 玩家两侧的原始场景得分之和 | 较高者胜 |
| 电车难题 | 玩家在两局中赢下的 sub-case 总数 | 较多者胜 |
| 凤仪亭 | 玩家获胜的那一局，貂蝉是否放弃连环计 | 放弃 > 继续 |

商鞅和本能寺比较两局原始总分。第 1 局为 P-A 对 Q-B，第 2 局为 Q-A 对 P-B，得分分别为：

```text
S(P) = 第 1 局 scoreA + 第 2 局 scoreB
S(Q) = 第 1 局 scoreB + 第 2 局 scoreA
```

`S(P)`、`S(Q)` 较高者赢下 pair，总分可以为负。两局得分都计入，大目标等奖励已包含在原始分数中。当前分值均为 0.25 的整数倍，可按四分之一分的整数单位精确相加。

电车难题每局含三个 sub-case，一个 pair 共六次案件裁决，按各自赢下的案件总数比较。同一案件在正反两局各算一次。例如 P 首局 3:0 胜、次局 1:2 负，案件总数为 P 4:2 Q，由 P 赢下 pair。若双方各赢三个案件，则 primary 相同。

凤仪亭比较双方各自获胜那一局的 `scheme` 字段：

| P 获胜局 | Q 获胜局 | primary 结果 |
| --- | --- | --- |
| 放弃连环计 | 继续连环计 | P 赢下 pair |
| 继续连环计 | 放弃连环计 | Q 赢下 pair |
| 放弃连环计 | 放弃连环计 | primary 相同 |
| 继续连环计 | 继续连环计 | primary 相同 |

### 4.2 Secondary differentiating factor：prompt token 总数

大海选和 64 强淘汰赛中，primary 相同时，比较两名玩家在本场景报名的两份策略 prompt 的 token 总数，较少者晋级。瑞士轮的单个 pair 不使用这一指标。

tokenizer 选用 OpenAI 的开源库 tiktoken，编码建议固定为 `cl100k_base`，所有参赛模型统一使用。

设 `tokens(text)` 为 `tiktoken.get_encoding("cl100k_base").encode_ordinary(text)` 返回的 token 数量，则：

```text
T(P) = tokens(P 的 A 侧策略 prompt) + tokens(P 的 B 侧策略 prompt)
T(Q) = tokens(Q 的 A 侧策略 prompt) + tokens(Q 的 B 侧策略 prompt)
```

token 按以下口径计算：

- 以报名截止时锁定的策略原文为准，保留空格、换行和标点，不额外 trim、改写或归一化。
- 两份 prompt 分别编码，再将 token 数相加。
- 只计玩家提交的策略文本，平台注入的角色卡、系统规则、隐藏目标、历史对话、裁判 prompt 和对局输出均不计入。
- 使用 `encode_ordinary`，形似特殊 token 的字符串也按普通文本编码。
- 报名截止时记录两侧及总 token 数，后续对局沿用该数值。
- tiktoken 软件和编码资产的版本在赛前公告中固定，比赛期间不升级。

若双方总 token 数仍相同，由组委会人工判断晋级方，并记录结果和理由。

参考：[tiktoken 官方仓库](https://github.com/openai/tiktoken)、[编码方法定义](https://github.com/openai/tiktoken/blob/main/tiktoken/core.py)。

## 5. 第一阶段：大海选

### 5.1 直通与海选名额

每个场景的名额分别设置：

- `K`：天梯直通人数，建议默认 100。
- `E`：大海选晋级人数，在 200–400 人之间提前公布，建议默认 256。
- `Q`：参加大海选的有效报名人数，不含直通选手。
- 瑞士轮人数 `N = K + E`，默认 356。

直通名单按报名截止时该场景的玩家天梯榜确定，保留当时的榜单快照，每名玩家只占一个名额。本文以已有玩家天梯榜为前提，不另定天梯 rating 算法。选手须完成报名并满足双侧参赛要求；未报名或不合格者的名额按快照排名顺延，补足 `K` 人。

直通选手从瑞士轮开始参赛，不再参加海选。同一玩家不能用不同智能体或版本占用多个名额。

### 5.2 海选分组与晋级

将 `Q` 人分为 `E` 个单淘小组，各组人数相差不超过 1，每组决出一名晋级者。组内采用固定单淘签表，不设积分赛和败者组。

有天梯排名的选手按排名蛇形分组，无排名者抽签补入剩余位置，抽签的随机种子公开记录。组内按种子排签，人数不足 2 的幂时补轮空，较高种子优先轮空。分组、签表和轮空安排在海选前锁定。

每次对阵打一个 pair，胜者晋级、负者淘汰，直到每组剩一人。双方各胜一局时，按第 4 节的顺序破同分。

例如 `Q = 2048、E = 256`，每组 8 人，打 3 轮后选出 256 人。`E = 256` 时，也可以画成一个大签表，打到剩余 256 人即停止。

分组单淘也适用于 `E = 200、300、400` 等名额，无须将晋级人数设为 2 的幂。

若 `Q ≤ E`，有效报名者全部晋级，瑞士轮人数为 `K + Q`。若 `Q > E` 且无弃权，海选共需 `Q - E` 个 pair，即 `2(Q - E)` 局。

海选晋级者与直通选手一同进入瑞士轮，全部从 0 分开始。

## 6. 第二阶段：瑞士轮

### 6.1 轮数与配对

按约 100 人直通、海选晋级 200–400 人计算，瑞士轮约有 300–500 人，建议打 9 轮。默认 356 人时，每人对阵 9 名对手，共打 9 个 pair、18 局，轮空或弃权除外。

轮数在赛前固定，不因某些选手提前达到特定积分而结束。晋级线如有同分，按第 6.3 节处理。

配对规则：

1. 首轮按赛前天梯排名确定初始种子，无排名者抽签排在其后。名单分为上下半区，对应位置配对。
2. 之后优先在同积分组内配对，按初始种子分上下半区；需要跨组时，向相邻积分组浮动。
3. 同一届瑞士轮内，两名玩家不得重复交手。出现冲突时调整组内配对，或跨相邻积分组浮动。配对算法及调整顺序赛前固定，配对结果留存备查。
4. 海选遇过的对手可以在瑞士轮再遇到，瑞士轮遇过的对手也可以在最终单淘再遇到。
5. 本轮所有有效 pair 结算后，再生成下一轮配对。

### 6.2 3 / 1 / 0 计分

| pair 结果 | 玩家本轮积分 |
| --- | --- |
| 胜 | 3 |
| 平 | 1 |
| 负 | 0 |

两局全胜者赢下 pair。双方各胜一局时，按第 4.1 节比较 primary：较优者获胜，得 3 分，对方得 0 分；primary 相同则判为平局，双方各得 1 分。单个 pair 不使用 secondary，不交由组委会人工判胜，也不加赛。

每轮按整个 pair 记一次积分，9 轮最高 27 分。

### 6.3 排名与晋级

积分榜依次比较以下指标：

1. 瑞士轮总积分，高者在前。
2. Buchholz 对手分：各轮对手最终瑞士轮积分之和，高者在前。未实战轮次见第 6.4 节。
3. 加权对手分（本赛制的 SB 口径）：每轮对手最终积分乘以自己在该 pair 取得的积分，再求和。胜乘 3、平乘 1、负乘 0，高者在前。
4. 实际赢下的 pair 数，多者在前，包含通过 primary 决出的胜场。轮空和弃权胜不算实际胜场。
5. 本场景两份 prompt 的 token 总数 `T`，少者在前，按第 4.2 节计数。

若所有指标都相同，由组委会人工裁定名次；涉及第 64 名时，由组委会判断晋级方，记录结果和理由，不另设加赛。此处的 token 比较和人工裁定只用于总榜排名，不参与单个 pair 的胜负判定，也不改变已完成 pair 的赛果或积分。

Buchholz 和加权对手分的思路参考 [FIDE 破同分规则](https://handbook.fide.com/chapter/TieBreakRegulations032026)。本赛事使用 3 / 1 / 0 权重，未实战轮次按第 6.4 节处理。

### 6.4 轮空与退赛

人数为奇数时，每轮一人轮空。优先在尚未轮空、也未获弃权胜的选手中选择积分最低者；同分时选初始种子较低者。可行时不重复轮空。

轮空记 3 分，不运行对局，也不生成场景分数、sub-case 或连环计裁决。退赛者保留已完成的成绩和积分，退出后续配对，不占 64 强名额。

轮空或已裁定弃权胜负的轮次，按本赛事的虚拟对手分计算：

```text
V(P, r) = P 在第 r 轮开始前的积分 + 1 + (R - r)
```

`R` 为总轮数，`r` 从 1 开始。虚拟对手以 P 本轮开始前的积分为起点，本轮及之后每轮各得 1 分。该轮 Buchholz 计入 `V(P, r)`，加权对手分计入 `V(P, r) × P 本轮实得赛事积分`。实际完成的 pair 使用真实对手的最终积分。

9 轮结束后，按第 6.3 节排序，取仍有参赛资格的前 64 名。直通选手和海选晋级者按同一规则排名。

若合格人数不足 64，全部晋级，最终签表补轮空，较高种子优先轮空。若人数明显偏离 300–500 人，主办方须在瑞士轮开赛前公告轮数，开赛后不再更改。

## 7. 第三阶段：64 强单淘

瑞士轮第 1–64 名依次成为淘汰赛 1–64 号种子。采用标准固定种子签表，首轮对阵为 `1–64、2–63、…、32–33`。签表按种子分区：1、2 号分处两半区，前 4 号分处四个四分之一区，前 8 号分处八个八分之一区。

签表在淘汰赛开始前固定，种子选手按各自排名安排相遇轮次。

| 轮次 | 晋级人数变化 | pair 数 | 单局数 |
| --- | --- | --- | --- |
| 64 强赛 | 64 → 32 | 32 | 64 |
| 32 强赛 | 32 → 16 | 16 | 32 |
| 16 强赛 | 16 → 8 | 8 | 16 |
| 四分之一决赛 | 8 → 4 | 4 | 8 |
| 半决赛 | 4 → 2 | 2 | 4 |
| 决赛 | 2 → 1 | 1 | 2 |
| 合计 | 64 → 冠军 | **63** | **126** |

每次交手完成两局后，按“两局胜场数 → primary → secondary → 组委会人工裁定”决定胜者。负者淘汰，不设败者组和复活，也不重排种子。默认不设季军赛，两名半决赛负者并列四强。

瑞士轮排名只决定种子和签表位置。所有对阵都按上述顺序判定胜负，决赛也一样；天梯排名和瑞士轮成绩不参与破同分。

## 8. 赛程与场次估算

按每个场景的默认配置，赛程如下：

```text
场景天梯前 100 名有效报名者 ────────────────────┐
                                             │
其他有效报名者 → 大海选：单淘小组 → 256 名 ─────┤
                                             ↓
                                    356 人，全部 0 分
                                             ↓
                              9 轮瑞士轮，每轮一个双局 pair
                           各胜一局先比 primary，相同才判平局
                                胜 3 分 / 平 1 分 / 负 0 分
                                             ↓
                                  按总榜顺序取前 64 名
                                             ↓
                       64 → 32 → 16 → 8 → 4 → 2 → 冠军
                   每轮双局，平局 primary → secondary → 组委会人工裁定
```

若某场景另有 2048 人参加海选，在没有退赛、弃权和失败重跑的情况下，场次为：

| 阶段 | 玩家人数 | pair 数 | 单局数 |
| --- | --- | --- | --- |
| 大海选 | 2048 → 256 | 1792 | 3584 |
| 瑞士轮 | 100 + 256 = 356，打 9 轮 | 1602 | 3204 |
| 最终单淘 | 64 → 1 | 63 | 126 |
| 合计 | 该场景 | **3457** | **6914** |

`Q ≥ E` 且瑞士轮人数 `N` 为偶数时，正常场次可按下式计算：

```text
总 pair 数 = (Q - E) + (N / 2 × R) + 63
总单局数 = 总 pair 数 × 2
N = K + E
```

四个场景若都有上述人数，共需 27,656 局。各场景按实际报名人数分别计算；单淘平局按既定顺序破同分，不增加对局。
