# 商鞅变法 Buff / Debuff List

状态：提案草稿  
适用范围：基于当前实际实现的 `shangyang-court`

## 1. 设计定位

这套 modifier 系统的目标不是改变商鞅变法的本质，而是给它加一个可测试、可构筑、可公开研究的外层。

推荐产品形态：

- `PvE 试炼场`：作为 `modifier lab`
- 玩家在 PvE 中测试 buff / debuff 与自己 prompt / doctrine 的配合
- `PvP`：每位玩家从公开池中选择 `1 个公开 modifier`，可为 `self-buff` 或 `opponent-debuff`
- 所有 modifier 在对局开始前公开

核心原则：

1. `大目标 +1` 仍然必须是全局最重要的分数轴。
2. 单个 PvP modifier 的期望摆动应尽量控制在 `0.10 ~ 0.20`，上限不超过 `0.25`。
3. 用 `0.1` / `0.2` 级别微调，而不是 `0.5` 级别重写规则。
4. 不改 `3 请求里 1 真 2 假` 这个核心张力。
5. 不做私有 judge prompt edit，不做隐藏 opponent sabotage。
6. 任何 turn-count 改动都必须保持 `偶数`，否则先手方会多一轮。

## 2. 推荐的 PvP 使用规则

S1 我建议这样开：

- 每位玩家只选择 `1 个公开 modifier`
- 这个 modifier 可以是 `self-buff`，也可以是 `opponent-debuff`
- 该 modifier 必须来自下方 `Launch PvP-safe pool`
- 在单槽位规则下，任何“镜像后效果完全一样”的词条只保留一个代表项
- 对局开始前，双方看到彼此选择

这样做的目的：

- 给 PvP 增加构筑表达
- 控制 modifier 对单局 shape 的扰动幅度
- 但不让 modifier 抢走 prompt 本体的戏份

## 3. Launch PvP-safe Pool

下面这些是我认为可以直接进公开 PvP 池的条目。

| ID | 名称 | 类型 | 精确效果 | 为什么这个数值合理 |
|---|---|---|---|---|
| B1 | 勘破一伪 | Buff | 开局前，你获知对手 `1` 条“确定为假”的请求 | 这是最干净的信息 buff。盲猜时命中率是 `1/3`；排除一条假请求后，会提升到 `1/2`，在猜测轴上的期望摆动约为 `+0.167`。够明显，但还没有大到盖过 `+1` 的主目标。 |
| B2 | 真意护符 | Buff | 如果对手正确猜中你的真请求，你的猜中惩罚从 `-1.0` 降为 `-0.8` | 这是在“被看穿”这一轴上做 `20%` 缓冲。之所以不是 `-0.75`，是因为 `0.25` 摆动对 launch PvP 来说偏大；`0.2` 更像一个二级保护层，不会让伪装 mini-game 失去威胁。 |
| B3 | 真请加重 | Buff | 你的真请求若被批准，得分从 `+0.5` 提升到 `+0.6` | 只加 `0.1`，因为真请求成功本来就是 secondary objective。若直接抬到 `+0.7`，会过度鼓励玩家牺牲大目标去硬推私利。 |
| B4 | 首伪减负 | Buff | 你的“第一条被批准的假请求”罚分从 `-0.25` 降为 `-0.15`；之后的假请求仍按 `-0.25` 算 | 只减第一条，是为了鼓励“有限度伪装”。如果对全部假请求减负，就会把“广撒网掩护真请”推成更优解，破坏当前设计张力。 |
| D2 | 严审压力 | Debuff | 如果对手正确猜中你的真请求，你的猜中惩罚从 `-1.0` 升到 `-1.2` | 同样使用 `0.2` 步进。`-1.2` 会让猜测更痛，但不会像 `-1.5` 那样使问询结果经常压倒辩论主轴。 |
| D3 | 真请减重 | Debuff | 对手真请求若被批准，其得分从 `+0.5` 降为 `+0.4` | 降 `0.1` 就够。若降到 `+0.3`，真请求成功会显得太不值钱，玩家会更倾向于只打大目标。 |
| D4 | 首伪加税 | Debuff | 对手“第一条被批准的假请求”罚分从 `-0.25` 升为 `-0.35`；之后的假请求仍按 `-0.25` 算 | 只加重第一条，最大摆动只有 `-0.1`。这样会抑制过度 decoy，但不至于让任何尝试伪装的玩家都显得像犯错。 |

## 4. PvE / Heat 可用，但不建议直接进入 PvP 选配池的强 mutator

这些 modifier 很适合用来做：

- PvE run 内奖励
- boss 节点强化
- heat / ascension 难度调节
- daily seeded trial 的公共环境词条

但它们太强，不适合一开始就做成“单个玩家可带入 PvP 的 side-select modifier”。

| ID | 名称 | 类型 | 精确效果 | 为什么这个数值合理 |
|---|---|---|---|---|
| M1 | 长听审 | Stage Buff | 本局总回合数从 `10` 提升到 `12` | `12` 的好处是双方各多 `1` 次发言，刚好是 `+20%` 话语预算。再往上到 `14`，就会明显改变商鞅游戏的节奏，让 build 更偏“拖长局”。 |
| M2 | 短听审 | Stage Debuff | 本局总回合数从 `10` 降到 `8` | `8` 会让双方各少 `1` 次发言，仍保留完整的“铺垫 - 试探 - 收束”结构。不能用 `9`，因为当前先手固定，奇数回合会让先手多一轮。 |
| M3 | 苛政急审 | Heat Debuff | 本局总回合数降到 `6` | `6` 是我愿意接受的最低值：双方还能各说 `3` 次，游戏仍然像“辩论”。低于 `6` 就太像 coin-flip 了，更像 prompt 抢开局而不是朝堂周旋。 |
| M4 | 开卷断伪 | Stage Buff | 双方开局都获知对手 `1` 条“确定为假”的请求 | 这是把 `B1` 做成全局环境词条。信息只下降一个台阶，不会让真请求直接裸奔。很适合做 PvE 中段的“较容易地图”。 |
| M5 | 真请偏重 | Stage Buff | 全局真请求奖励从 `+0.5` 提升为 `+0.6` | 仍只加 `0.1`。作为环境词条时，它会鼓励更积极地争取真请求，但不会推翻“主目标仍比单条真请求更重要”的事实。 |
| M6 | 真请偏轻 | Heat Debuff | 全局真请求奖励从 `+0.5` 降到 `+0.4` | 同理，降 `0.1` 是为了改变 run 风格，而不是重写 game plan。再低会过度稀释隐藏目标轴。 |
| M7 | 伪请重税 | Heat Debuff | 全局假请求罚分从 `-0.25` 升到 `-0.35` | `-0.35` 会明显惩罚乱撒 decoy，但不会像 `-0.5` 那样让“任何假请求被批都接近灾难”。 |
| M8 | 伪请轻税 | Stage Buff | 全局假请求罚分从 `-0.25` 降到 `-0.15` | `-0.15` 可以鼓励玩家练习“更大胆的伪装打法”。不能降到 `0`，否则假请求几乎没有成本，会直接扭曲博弈。 |
| M9 | 严刑审问 | Heat Debuff | 全局“被猜中真请求”罚分从 `-1.0` 升到 `-1.2` | 仍只加 `0.2`。它让问询更可怕，但不至于把问询抬成主胜负轴。 |
| M10 | 宽刑审问 | Stage Buff | 全局“被猜中真请求”罚分从 `-1.0` 降到 `-0.8` | 这是适合新手练习的宽容环境。因为只减 `0.2`，玩家仍有动力伪装，不会完全无视问询。 |

## 5. 我会保留为“Daily / Seasonal Public Mutator”，但不做 side-select loadout 的类型

下面这些词条我认为可以存在，但更适合作为：

- daily seed 的公共规则
- 一个赛季所有人共用的环境修改
- PvE 中的特殊节点词条

而不是让某一位玩家单方面带入 PvP。

| 名称 | 精确效果 | 为什么不建议做成一边选配 |
|---|---|---|
| 可行性至上 | judge prompt 中额外强调“执行细节和落地路径” | 它会明显偏爱某些 archetype，但强度很难用干净数值表达，更适合做赛季公共环境。 |
| 守成倾向 | judge prompt 中额外强调“宗室稳定与政治风险” | 会实质改变秦孝公的 baseline。作为全体共享环境很好，作为单边 buff 太像暗改裁判。 |
| 改革急迫 | judge prompt 中额外强调“秦国积弱，不变则亡” | 同理。它是高质量环境变体，但不适合作为 side-select 装备。 |
| 重修辞 / 轻修辞 | judge 更重视文气，或更轻视空泛修辞 | 有意思，但数字不可见，平衡成本高。先放在公共 mutator，不放进 side loadout。 |

## 6. 我不会加入池子的类型

这些不是“以后再说”，而是目前我明确不建议做。

| 类型 | 为什么不建议 |
|---|---|
| 直接暴露真请求 | 这会把 `3 选 1` 的隐藏张力直接打穿。 |
| 改成 `2 真` 或 `4 请求` | 这已经不是“给当前商鞅加 modifier”，而是在重做底层 game design。 |
| side-specific `+1` 完整发言轮 | 单边多一整轮会明显改变博弈结构，强度远大于 launch modifier 的设计预算。 |
| 私有 judge prompt edit | 会摧毁当前系统最重要的公平资产之一：judge 公开。 |
| 隐蔽 opponent sabotage | 太像 prompt 注入，不像游戏机制；也很难复盘。 |
| 任意改模型温度 / top-k | 这会从“策略游戏”滑向“采样噪声游戏”。 |

## 7. 最终建议

如果现在就要收敛成可做版本，我建议：

### PvP S1 只上这 7 个

- `勘破一伪`
- `真意护符`
- `真请加重`
- `首伪减负`
- `严审压力`
- `真请减重`
- `首伪加税`

原因：

- 每位玩家只带 `1` 个公开 modifier，复杂度更低
- 都有清晰数值
- 都围绕当前真实实现的三条轴在微调
- 都不会把 game feel 改得太远

### PvE / Heat 先上这 6 个环境词条

- `长听审`
- `短听审`
- `开卷断伪`
- `真请偏重`
- `伪请重税`
- `严刑审问`

原因：

- 玩家能很快感觉到差异
- 数值容易讲清楚
- 它们特别适合作为“run 里拿到一个词条，下一场看看会怎样”的试炼场玩法

一句话总结：

> PvP 选配池要做“小而清晰的微调”；PvE / Heat 词条才适合做“更强的环境变化”。

## 8. 本质分类总表

这里不按“buff / debuff 长什么样”分类，而按它本质上改动了哪条核心资源轴分类。

### A. 信息类

它改变的是：

- 你知道什么
- 对手知道什么
- 双方对真请求空间的压缩程度

这类最贴近当前商鞅游戏本体。

归入这一类的条目：

- `B1 勘破一伪`
- `M4 开卷断伪`

### B. 赔率类

它改变的是：

- 同样一个事件，值多少钱
- 某个次目标值不值得冒险

它不改信息结构，也不改回合结构，只改 payoff。

归入这一类的条目：

- `B2 真意护符`
- `B3 真请加重`
- `B4 首伪减负`
- `D2 严审压力`
- `D3 真请减重`
- `D4 首伪加税`
- `M5 真请偏重`
- `M6 真请偏轻`
- `M7 伪请重税`
- `M8 伪请轻税`
- `M9 严刑审问`
- `M10 宽刑审问`

### C. 节奏类

它改变的是：

- 一局里总共有多少操作预算
- 铺垫、试探、反打、收束的空间

这类往往比赔率类更强，因为它改的是整局形状。

归入这一类的条目：

- `M1 长听审`
- `M2 短听审`
- `M3 苛政急审`

### D. 评审类

它改变的是：

- 秦孝公更看重什么
- 哪种 archetype 更占便宜

这类本质上在改 judge frame。

归入这一类的条目：

- `可行性至上`
- `守成倾向`
- `改革急迫`
- `重修辞 / 轻修辞`

### E. 规则类

它改变的是：

- 这还是不是同一个商鞅游戏
- 核心协议层有没有被改写

这一类不该和普通词条混在一起。

归入这一类的条目：

- `直接暴露真请求`
- `改成 2 真 或 4 请求`

### F. 不透明 / 不建议类

这类不是因为数值过强，而是因为它会破坏可解释性和公平性。

归入这一类的条目：

- `私有 judge prompt edit`
- `隐蔽 opponent sabotage`
- `任意改模型温度 / top-k`

### G. 设计外层类

这类不是单局词条，而是 roguelite 外层 progression。

它改变的是：

- 你未来能选什么
- 你能挑战哪些 run
- 你能带哪些构筑件

这类不属于当前 buff/debuff 池，但最好单独记住。

典型形式：

- 解锁新的 doctrine card
- 解锁新的 preset boss
- 解锁新的 heat
- 解锁新的公共 modifier pool

### 一句话归纳

如果只从产品落地上分：

- `PvP 公开选配池`：优先用 `信息类 + 小幅赔率类`
- `PvE / Heat / Daily 环境词条`：优先用 `节奏类 + 评审类 + 强赔率类`
- `不该混进普通池子里的`：`规则类 + 不透明类`
- `roguelite 外层系统`：`设计外层类`
