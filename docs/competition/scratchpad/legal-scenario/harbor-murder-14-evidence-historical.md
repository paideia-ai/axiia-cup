> 建议部署场景 ID：`legal-harbor-murder-jury`
> 建议部署标题：`码头疑云`
> 建议部署参数：12 轮交锋；每次发言不超过 3 句话；赛后提交事实叙事图。
> 建议隐藏层：隐藏 planted truth、证据可靠性权重和陪审团证明阈值；双方不知道底层最优叙事。
> 程序化确定性判决：是，底层为 Weighted Argumentation Framework。

## 背景

海港仓库夜间发生命案。被害人是港口承包商纪川，死亡时间约在 23:10 到 23:40。被告顾衡是与纪川有合同纠纷的货运经理。控方指控顾衡在仓库后门杀害纪川；辩方主张第三人趁停电进入仓库，顾衡只是发现尸体后惊慌离开。

陪审团必须决定：控方是否排除合理怀疑。

## 角色

| 角色 | 控制方 | 立场 |
|------|--------|------|
| **控方检察官** | 玩家甲的 LLM | 证明顾衡故意杀人且排除合理怀疑 |
| **辩方律师** | 玩家乙的 LLM | 建立合理怀疑，提出更一致的替代叙事 |
| **程序化陪审团** | 系统 verifier | 根据论证图和证明阈值计算裁决 |

## 论证图

底层以论点为节点，支持、攻击、削弱为边。

```text
A1: 顾衡有作案机会
A2: 顾衡有强动机
A3: 顾衡处理现场或逃离
A4: 顾衡就是杀人者
D1: 罗某有独立进入机会
D2: 死亡时间不能锁定顾衡
D3: 关键物证可被无害解释
D4: 控方未排除合理怀疑
```

例子：

```text
E1 + E3 supports A1
E8 supports D1
E9 attacks E8 reliability
E14 supports D2
A1 + A2 + A3 supports A4
D1 or D2 attacks A4 beyond reasonable doubt
```

## 游戏流程

### 第一阶段：开案叙事，2 轮

控方和辩方各用一轮提出完整故事线。故事线必须解释死亡时间、进入路径、动机和离场行为。

### 第二阶段：证据攻防，8 轮

双方围绕证据可靠性和推理链展开。每次发言应至少完成一种动作：

- 强化一条证据的可靠性；
- 削弱对方证据；
- 连接两个事实形成推理链；
- 指出对方叙事无法解释的异常；
- 承认弱点并给出法律上仍可接受的解释。

### 第三阶段：结案陈词，2 轮

控方必须说明为什么已排除合理怀疑。辩方必须说明哪个替代叙事足够合理，不必证明真正凶手是谁。

### 第四阶段：结构化提交

双方提交：

```json
{
  "acceptedArguments": ["A1", "A2", "A3", "A4"],
  "rejectedArguments": ["D1", "D2"],
  "verdict": "有罪",
  "keyEvidence": ["E1", "E3", "E6", "E7"],
  "reasonableDoubtPath": [],
  "explanation": "不超过 220 字"
}
```

辩方若主张无罪，应在 `reasonableDoubtPath` 中列出形成合理怀疑的最小证据链。

## 程序化陪审团

verifier 从隐藏权重计算最优 accepted argument set，再应用证明标准：

```text
guilty_score = support(A4) - strongest_reasonable_doubt_path
if guilty_score >= threshold:
    verdict = 有罪
else:
    verdict = 无罪
```

| 项目 | 控方得分 | 辩方得分 |
|------|----------|----------|
| verdict 与 verifier 一致 | 30 | 30 |
| accepted/rejected arguments 接近最优集合 | 35 | 35 |
| 关键证据链选择正确 | 20 | 20 |
| 合理怀疑路径处理正确 | 15 | 15 |

## 胜负规则

得分高者胜。若 verifier 判定有罪且控方提交也有罪，控方通常获得基础优势；若辩方识别出 verifier 中最强合理怀疑路径，即使 verdict 最终有罪也可在论证图分数上反超。

## 核心张力

1. 控方要把多个中等强度证据连接成单一叙事，而不是堆砌怀疑。
2. 辩方不必证明罗某杀人，只需构造足以破坏阈值的合理路径。
3. 证据可靠性本身是争点，强证据若被污染可能变成弱节点。
4. 最终胜负由全局论证图决定，局部漂亮的反驳未必最优。
