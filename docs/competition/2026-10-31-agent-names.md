# 智能体名称、比赛快照与编号

本次在历史条 PR #288
的双人物布局上调整身份文案，保留布局、胜负颜色、角色名、筛选、未读回执和战报入口。

## 显示规则

- 智能体默认名称为 `#ID`；自定义名称非空时使用名称。
- 历史条：我方显示智能体名称，对方显示「玩家名 ·
  智能体名称」。角色仍在原角色行。
- 对局详情和 transcript 的参战方卡片显示智能体名称，不显示版本序号或版本全局
  ID。
- 点击参战方带上实际 `versionID` 和
  `matchID`，进入自己的主页或他人的资料页，选中并滚动到该版本。原生新标签页行为保留。
- 约战 ID 仍可复制，复制的值是原始数字，兼容现有按 ID 约战接口。
- 预设对手使用比赛固定的
  `presetLabel`；旧接口没有名称时显示「预设智能体」，不显示内部 preset key。
- 智能体编号为 `#125`，版本全局 ID 为 `V·928`，智能体内部版本序号仍为
  `v3`。版本管理、公开资料、筛选、出战和锦标赛中的版本 ID 使用相同格式。

## 名称的时间语义

后端 `MatchParticipantDTO.agentName`：

1. 未开始且未结束的比赛使用当前智能体名称。
2. `dispatchMatch` 在首次设置 `dispatchedAt`
   的同一事务中保存双方名称，未命名保存 `#agentID`。
3. 开始后改名、清空名字、重新读取或重复 dispatch 不改写快照。
4. 已开始或已结束的旧记录缺失快照时不使用当前名称，客户端回退到稳定的
   `#agentID`。无法从现有记录可靠恢复过去的名称，不做推测性回填。
5. NPC 名称来自比赛固定的脚本及参数，与其模型和角色使用相同历史来源。

前端依赖配套后端新增的可选 `agentName`、`presetLabel`
字段。部署旧后端时只能显示默认编号和预设通用名称。应先部署配套后端，再发布前端。名称快照保存在现有比赛
JSON 配置内，不新增数据库表或列。

## 本地检查

在 `v2/web` 运行 `deno task preview:agent-naming`，打开
<http://localhost:6063/preview>。

这是正式构建加本地样例
API，不访问线上或执行真实模型对战。样例包含同一智能体改名前、改名后、旧记录缺失快照及队列记录；可在智能体主页实际操作重命名，再返回历史检查只有排队记录变化。样例改名仅影响当前浏览器会话。

`playwright.agent-naming.config.ts`
检查手机和桌面的改名、历史名称、参战方名称、版本定位、公开资料、编号与预设名称。后端
Store/API 测试负责验证真实事务的快照及排队行为，前端样例不替代后端验收。
