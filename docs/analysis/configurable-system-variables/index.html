可配置系统变量

合并 Supabase 评论、UI Spec v1–v4、DESIGN_SPEC Git 历史与当前场景 schema 后得到的产品配置清单。

整理日期

2026-09-02

管理方式

文件 + CLI

结论：当前 v3.4 C2 注册表覆盖了主要运营旋钮，但历史规格还包含 场景执行配置，并留下“重复约战限次”“turn_count 默认值”“judge_rounds” 三项必须先裁决的冲突。

确认需要可配置的旋钮

变量 作用域 规格口径 默认 / 状态
stats.min_battles_per_agent 全局 按 agent 的对局数决定是否展示场景统计；不按胜率 数值未定；前端不得写死
limits.daily_battles_per_player 每玩家 每日总对战次数；只扣发起人；触顶拒绝入队 数值未定
limits.concurrent_battles_per_player 每玩家 同时排队或运行的对局上限 数值未定
limits.pvp_daily_battles_per_player 每玩家 PVP 每日次数，独立于每日总量 数值未定
gates.pvp_distinct_wins_per_side 玩家 × 场景 × 侧 每一侧分别击败 N 个不同 PVE-NPC；约战双方均须达标 N=1；N ≤ NPC 数
pve.default_npc_count 全局默认 每场景的默认 PVE-NPC 数量 2
onboarding.scenario_id 全局 新人首战默认场景 曾建议商鞅；待确认
onboarding.side 全局 新人首战默认执方 待定
onboarding.opponent_npc_id 全局 新人首战自动派发的“最容易”NPC 待定
models.allowed_player_models 全局 由配置文件/只读接口下发；选择结果随版本快照 清单可变
visibility.matrix 全局 按资源 × 观众身份决定可见性 提示词、diff、玩家 trace 仅所有者
scenario.difficulty 每场景 场景难度 简单 / 中等 / 困难
scenario.beginner_friendly 每场景 独立新手标记，不由 difficulty 推导 Boolean
notifications.preferences 每玩家 总开关、逐类偏好、强制通知、默认值与持久化 Future；当前全部默认开启
ops.block_trials_during_tournament 运营 赛事运行期间是否阻挡全部试炼 规格已确认

场景配置必须支持

Flow

对局流程

turn_count、stage_structure、 examination_mode、examination_questions、 历史字段 judge_rounds。

Randomization

隐藏信息

两侧隐藏信息池、false_info_count、 true_request_count 及每局抽取分配规则。

Evaluation

裁判与计分

Judge/scorer 模型与 prompts、计分模式、维度、权重、惩罚、场景专属 scoring script/schema。

Content

角色与构建

两侧角色卡、目标、边界、立场/请求项、开场白、系统角色模板、MCQ decks。

Opponents

PVE-NPC

NPC 列表、所属侧、名称、提示词、模型、难度、排序，以及“最容易”对手定义。

Metadata

场景基础信息

名称、学科、摘要、背景、难度、新手标记、预计时长、上线时间。

先裁决，再实现

Conflict 01

重复约战限次

历史规格分别出现“不额外限制”“同一对手每日 M 次”“完全相同四版本阵容每日 X 次”。最终只能保留一种口径。

Conflict 02

turn_count 默认值

产品规格默认 20；当前数据库 schema 默认 10。

Conflict 03

judge_rounds

历史规格默认 3；当前 schema 没有独立字段，需决定恢复或由新问询 schema 正式取代。

Open Value

统计展示门槛

计算口径已定，具体对局数仍未确认；可以不展示给玩家，但不能缺少配置值。
