# 加载提示防闪调整

基于 `origin/main` 的 `cd71581`，独立 worktree `axiia-cup-loading-feedback-delay`。

## 行为

- 骨架和顶部进度条都在持续等待 350ms 后才显示，替代原来的 150ms 门槛。
- 显现使用 150ms 的柔和淡入，降低略超门槛的请求造成的闪烁感。
- 数据到达立即显示，不设置动画最短播放时间。
- 后台刷新保留正文；reduced motion 下仍延迟显示，但不播放淡入或移动动画。
- 缓存、预取、接口和内容入场规则保持原样。

350ms 是等待提示的起点，并不保证任何临界请求都完全没有可见变化。例如
400ms 完成的请求可能显示一小段淡入。提前完成的请求取消定时器，不显示提示。

## 预览

在 `v2/web` 执行：

```sh
deno install --frozen
deno task storybook --host 127.0.0.1 --port 6084 --no-open --exact-port
```

打开 <http://localhost:6084/iframe.html?id=preview-navigation-loading--below-threshold&viewMode=story>。
页面顶部可选择 50、200、300、400、900、1800ms 六档模拟接口延迟。
「重置演示」重新体验首次加载；「刷新当前页」观察保留正文时的进度提示。
使用实际 AppRoutes 和页面组件，所有业务接口为只读演示样本。

模拟延迟指单次接口的处理时间，不包含本地浏览器调度、开发模块或字体加载；
有串行请求的页面，总等待也可能更长。缓存回访通常直接显示内容。

本地录屏、截图及测量保存在 `.local/loading-delay-preview/`，不提交二进制文件。

## 验证

- 导航浏览器回归包含 50/200/300ms 不出现骨架或进度条，以及慢速后台刷新保留正文、
  请求完成后立即撤下进度条。
- 沿用首次失败、权限失效、移动端 reduced motion、缓存和旧响应竞争回归。
- 格式、lint、应用/测试类型检查、生产构建通过；导航浏览器测试 12/12、
  Storybook 测试 110/110 通过。构建保留既有的大 chunk 和插件弃用提示。
- 单独录制的预览中，50/200/300ms 档未显露骨架；400/900/1800ms 档在
  挂载后约 353–356ms 开始显露。该次内容可用时间分别约为
  97/300/354/440/926/1856ms，只作为本地演示记录，不代表生产性能。
