# 我的智能体 UX demo — 2026-09-09

Run from `v2/web`:

```bash
deno install --frozen
deno run -A npm:vite --config vite.demo.config.ts
```

Open <http://localhost:5190/demo.html#/my-agents>.

The demo uses the current `src/styles.css`, Button, Input, Textarea, Badge,
Card, and VersionList components. Its shell follows the existing AppShell
layout, including desktop navigation and the mobile bottom bar. Clickable
controls share a pointer cursor, including menus and popovers. Text inputs keep
the text cursor; disabled controls use the unavailable cursor. These rules are
scoped to the demo document and do not change hover colors.

The three agent pages implement the requested information hierarchy:

- 我的智能体: scenario groups, minimal descriptions, whole-row links, and one
  robot-plus icon per side, beside the role description. Original neutral dark
  colors. No row management buttons or version metadata. Role descriptions
  appear once per side; compact agent rows keep names and entry highlighting.
  Scenario titles link to their scene information pages. Scenario headers retain
  the original per-side completion badges and entry-readiness summary, using the
  shared Badge styles. The selected entry agent on each side has a subtle red
  accent border; changing the entry version to another agent moves the highlight
  with it.
- 智能体主页: an always-visible horizontal list of same-role agents (including a
  single agent), with a trailing robot-plus icon to create another agent; a
  white pencil-plus icon beside the version count enters the builder (20px
  pencil with a small plus, 44px mobile touch target). The page also supports
  inline renaming, empty-agent deletion, version contents, clipboard copying,
  selection of any two versions for comparison, entry selection, and simulated
  battle configuration. Existing VersionList is reused with compact actions:
  chevrons expand/collapse text, the standard overlapping-pages icon copies the
  full strategy to the clipboard, and a check on the right selects the entry
  version. A sword icon opens the selected version's battle configuration.
  Expand, copy, entry selection, and creation controls use icons with accessible
  names and hover titles. Copy and battle keep fixed positions on the left;
  expand/collapse sits on the right when needed. Battle retains a sword icon
  plus the visible 出战 label. Selection shows “已设置用此版本参赛” for 2.4
  seconds. Expand/collapse icons appear only when the prompt exceeds the
  three-line preview at the current width, and update when the viewport or fonts
  change. There is no separate entry-readiness panel or dual-side status
  reminder on the agent home. The shared component defaults to its existing
  controls outside this demo.
- 智能体构建器: an initially blank strategy textarea, local draft persistence,
  and save-and-return. Strategy helpers sit above the editor so they are visible
  immediately on mobile. A compact secondary row offers model selection, an
  optional version note, and independent persona selection for Honnoji. The copy
  icon beside the strategy label copies the current unsaved draft verbatim. MCQ
  assembly and the external-AI meta-prompt workflow open in optional dialogs.
  Notes use an icon beside Save; a small popover holds the optional input, and a
  dot on the icon indicates a nonempty note. Escape, the close icon, and
  clicking outside dismiss the popover without discarding the draft note. An
  independent 角色系统提示词 accordion shows the original read-only role
  template without filling or changing the strategy draft. There is no version
  list in the builder.

Model choices in this demo are a sample from the sibling v2 ModelCatalog, not a
live production allowlist. Draft model and notes persist locally. A new version
records its selected model, persona, optional note, and save timestamp; notes
clear after saving, while the selected model carries forward. If there is no
draft selection, the latest version's model is inherited, including a model no
longer present in the example list. Existing imported timestamps stay unknown.

New agents open their home page. Saving creates a version without automatically
changing the entry version. Entry selection is exclusive within a scenario side.
Creating another same-side agent requires an opposite-side saved version; agents
with saved versions cannot be deleted. The name's ellipsis menu contains rename
and delete; there is no separate management card. Rename edits the title in
place (Enter saves, Escape cancels, with icon controls for touch). Delete
requires confirmation; saved agents show a disabled item and
“已有版本，无法删除”. Copying shows a check briefly on success and leaves the
route and draft unchanged.

Named agents' IDs and all version IDs, prompts, models, and battle records were
not in the paste. Negative internal keys never appear as production IDs. At the

Version comparison uses a compact row with two version selectors; the result is
collapsed by default. Opening the section compares the latest two versions;
changing a selection opens and updates the result automatically. Each selector
omits the other selected version. Dropdowns show version numbers, optional
notes, and secondary model labels, without internal IDs. Removed and added text
is highlighted in two columns (stacked on mobile); identical prompts get a short
status message. Zero versions omit the section; one version shows next-save
guidance. Grapheme-aware comparison preserves whitespace and emoji. For very
large changed spans, it highlights the changed span as a whole to bound memory.

No application API or model is called. Battle configuration stops at
confirmation. The meta-prompt workflow runs in the user's external AI: copy the
provided request to DeepSeek or another AI, then paste its final strategy
verbatim into the main builder input. The meta-prompt dialog has no input box;
it only shows the request and copy action, with the usual top-right close icon.
Only that generated strategy is filled into the draft; the meta-prompt itself is
not saved as strategy. Navigation outside the three-page flow explains the demo
boundary. Scene information is included in the demo.

The demo has its own HTML entry and Vite configuration. Production routes are
unchanged. The original ScenarioDetailPage now shares ScenarioDetailContent with
the demo: the same background, illustrations, participant cards, hidden-goal
accordions, judge/scoring information, and timeline render from the original
scenario modules. Only inventory and navigation callbacks use local demo data.
Scene-page creation opens the existing demo dialog, and 查看我的 returns to the
inventory. Live match statistics and PVP unlock progress are omitted because the
pasted inventory does not contain them. The `axiia-cup-v2/packages/axiia-web`
fallback frontend was inspected; the visual baseline is this repository's
current `v2/web`.

- MCQ uses `deckFor`, `assembleDeck`, and `deckComplete` from the existing
  frontend, including the original role-specific questions and fragments, live
  preview, required-answer checks, and prompt-unit counting. No generic
  replacement questions are used.
- Honnoji's presets are keyed by persona, so its preset dialog first offers the
  original two personas for the agent's side. Switching personas resets the
  questionnaire; filling saves the selected role with the draft, and saving
  includes that role in the local version's options. No role is inferred from
  the pasted inventory.
- Meta-prompt uses `metaPromptFor` with the existing scenario module: scenario
  context, side-specific victory conditions, scoring, and official role
  template. Clipboard failure leaves the source selectable for manual copying.
- The demo removes the first-draft initialization gate. Both tools remain
  visible with an empty or nonempty draft and before or after saving versions.
  Filling a preset over different existing text asks for confirmation; cancel
  preserves the draft, and replacement never changes saved versions.
- For a role without a registered deck, the preset dialog explains that no
  presets are available and links to the AI helper. Meta-prompts work
  independently of decks; the Legal Harbor ID resolves to its original scenario
  module.
- The demo retains `raw`, `mcq`, or `builder` initialization provenance in local
  draft/version records. MCQ filling records `mcq`; direct pasting into the main
  editor follows `raw` input. Existing records may retain the earlier `builder`
  method. Filling creates a draft; saving creates the version.
- The local demo uses `PROMPT_UNIT_LIMIT` (1000), not a live configuration
  value.

The demo enforces its 1000-unit limit for new versions, matching the preset fill
gate. Over-limit drafts remain editable and persist locally without truncation;
saving is disabled until they fit. The demo empty version state shows only
还没有保存过版本.

Deleting an empty agent selects the next same-role agent, falling back to the
previous one. If none remain, the same role keeps an empty home with its create
icon; it never redirects to the inventory automatically.

Agent creation uses a compact anchored popover on desktop and a bottom sheet on
mobile, with a title, optional name, close icon, and Create action. Opening
focuses the name; Enter submits, including an empty name. The existing
opposite-side gate still appears when needed. The sheet tracks the visual
viewport to stay above the software keyboard.
