## 文件与复现

- `manifest.json`：供试听界面加载的十一项数组；`id`、`name`、`description`、`duration`、`file`、`character`。
- `*.wav`：44,100 Hz、双声道、16 位有符号 PCM WAV；时长 0.58–1.75 秒。
- `render.py`：01–10 使用 Python 3 标准库合成器与固定随机种子；11 通过子进程调用
  Deno 导出器。无第三方包、网络请求或外部素材。
- `export-original.ts`：直接导入现有产品声音函数，把它返回的 Float32 序列量化为
  PCM16，原样复制为两个相同声道，不重新合成、归一化、滤波或添加包络。
- `metrics.json`：对实际编码后的 WAV
  进行测量，包含文件哈希、头信息、峰值、RMS、首尾静音和削波检查。11
  额外记录与实际产品函数逐样本比较的误差及原始 Float32 哈希。
- `verification.json`：重复生成的一致性，以及独立 FFmpeg
  响度和真峰值检查。FFmpeg 不是生成依赖。

在本目录执行（01–10 使用 Python 3；完整生成及检查另需项目使用的 Deno）：

```sh
python3 render.py
python3 render.py --check
```

生成时覆盖本目录十一个音频及对应 manifest、metrics；`--check`
只读验证，比较已记录的哈希与实际文件，并重新调用产品声音函数验证 11。添加 11
前后，01–10 的 WAV 哈希完全一致。

## 电平与尾音

01–10 使用平滑起音、指数衰减和尾部缓降；末尾至少保留 18
毫秒数字静音。输出保留至少 6 dB 的样本峰值余量，没有削波。每段按有效声音窗口的
RMS 约束响度，而不是把停顿和结尾静音计算为需要补偿的音量。

11 保留原版函数自己的电平和尾音，不应用新方案的响度或静音要求。导出器验证 WAV
与直接量化的原版完全一致，且按 32767 和标准 PCM 解码的 32768
两种除数恢复后，与源 Float32 的最大误差都不超过 `1 / 32767`。

`active_rms_dbfs` 使用高于 −45 dBFS 的 20 毫秒窗口；01–10 的目标约 −23
dBFS。它是短提示音的能量比较值，不是 LUFS。FFmpeg 的短音频综合 LUFS
仅用作交叉检查；此长度下门限与不同尾音比例会影响结果，不能直接等同于主观音量。`last_50ms_rms_dbfs`
为 `null` 代表数字静音。

默认建议从 01 或 05 开始试听；07 更有仪式感，10
最克制。试听页面的音量控制作用于所有方案，选定后仍可单独微调产品播放音量。
